# HD-2D P2：纯烘焙移轴

状态：只在 `?dof=on` 时生效；`?dof=off`（默认）不创建任何对象、不申请任何纹理。
设计原文是仓库外的 HD-2D 技术路线 §13，这里只记录落地后的实现口径与实测。

## 1. 管线

1. **S-0 断言**（`dof-view.ts`）：地形贴图的源必须是 `HTMLCanvasElement`，
   否则直接抛错、整条路径停掉。Phaser 升级若把 `generateTexture` 换成 GPU readback，这里先红。
2. 离屏 canvas（世界全尺寸）→ `drawImage(地形纹理)` → **按 depth 顺序叠上闭包里的静态入口**
   → `getImageData`。
3. `boxBlurRGBA`：可分离整数 box；横 pass 存 32 位原和，纵 pass 唯一一次除法；边缘复制；
   `k = 2r+1` 恒为奇数；单次迭代。合成后先扫一遍 alpha，任何 ≠ 255 直接失败（M-15）。
4. 双缓冲 `world-blur-a/b`：写非当前图 → `putData` → `refresh` → `setTexture`。
   **永不 `textures.remove`**（同 key 重建会停在上一版，`bake.ts` 的老坑）。
5. 版本向量 `(terrainVersion, structuresVersion)`：帧首比对，变化才重建。
   潮位 / 天气 / 雾 / 人物都不在向量里——否则糊图过期节奏会等于潮位节奏。
6. 行裁切窗：`focusWindow(worldView.y, zoom, height)`，裁切高 = 焦点带高 − 1（隔离行），
   1 px 硬边、不做渐变。`worldView.y` 是视野上沿，不是 `scrollY`（zoom ≠ 1 时两者不同）。

## 2. 闭包里到底有什么

| depth | 入口 | 文件 |
| --- | --- | --- |
| -10 | 地形纹理 | `bake.ts` |
| 0 | 痕迹 `trails` | `decor.ts` |
| 1 | 铺装 `roads`、铁轨 `track`、街面 `street` | `decor.ts` / `setting-scenery.ts` |
| 1.5 | 滩涂补绘 `ground` | `scene-artbook.ts` |
| 4 | 桥 `bridge`、渡口木栈/桩/船 `fixtures` | `setting-scenery.ts` / `harbor-view.ts` |
| 5 | 远景背板 `backdrop` | `scene-artbook.ts` |
| 6 | 岸台 `quay` | `scene-artbook.ts` |

运行期读数 `sources = 9`。打标用 `markDofStatic`，收集只认这个标记——不按 depth 猜，
所以任何后来新增的贴地入口不标就不会悄悄进闭包（少一层会被 C7 抓到）。

**没进闭包的静态入口，只有一类：depth ≥ 1000 的建筑 / 道具 / 立面补绘。** 原因是结构性的：
它们的 depth 与人物逐行交错（`sceneryDepth` 按落地行、`villagerDepthAt` 也按落地行），
一张平面糊图不可能同时「压在建筑上、垫在人物下」。Phaser 4 的 WebGL 后端又不支持
GeometryMask（只打警告），所以也没有「画原件但按行遮掉」这条路。这就是 S-4 未闭合项。

## 3. 深度位置

`DOF_DEPTH = 999`：压在整条贴地带之上（闭包里最高是 6），在人物与立体构件的 `ALTITUDE = 1000` 之下。

- 糊图必须盖住原件才看得见，所以 depth 必须高于闭包里所有层；
- 原件不需要隐藏（不做 mask），被糊图整片盖掉；
- 潮位（3）、灯影（3.2）、倒影（3.2）不在闭包里，也不在糊图之上——它们仍是原件，
  在远带里保持清晰，这是已知代价（§13 的潮位离散化留给 S-5/S-8）。

> 第一版曾把糊图放在 -5（只糊地形）：远带里木栈、栏杆、船全是锐边，读成「水变柔了」，
> 而且为了不盖掉轨道还试过 2.9，结果码头轨道（0）整条消失。现在的口径是
> 「闭包取到贴地带最上层、糊图压在它上面」，不再需要任何让位。

## 4. 核尺寸：由目标反差反推，不预先拍档

§13.3.2 已经改写：**核上限由目标反差决定，不再预先拍档。** 反推式是

```
k ≥ ⌈C / T⌉，且 k 取奇数
```

`C` 是同一组边缘在 `?dof=off` 下的最大通道梯度，`T` 是判据要求的糊带上限（C7 取 20）。
整数可分离 box 的台阶梯度上限就是 `C / k`，所以这条式子是**上下界**，不是经验值。

先按旧档位表跑 B1（r=1/k=3），摆件进得来、但**看起来仍是锐的**：

| 摆件边缘（世界像素窗口） | `?dof=off` | B1（k=3） | 现档（k=11） |
| --- | --- | --- | --- |
| 渡口木栈左竖边 | 180 | **61** | **17** |
| 街面栏杆横边 | 73 | **25** | **7** |
| 船壳横边 | 176 | **56** | **11** |

按本机位最大反差 C=180、T=20 代入：`k ≥ ⌈180/20⌉ = 9`，取奇数 k=11（r=5）。实测 17/7/11 全过 <20。
**B3=k7 的原始上限被 180 反差实测推翻**：它同一组边只能到 26/21/25，`<20` 在数学上不可能。

- **核的实现没变**（可分离整数盒式、滑动和、边缘复制、k 奇数、单次迭代），只改了窗口半径；
- 代价是远带里去重色数从 239 涨到 **4,630**（k=3 时会少得多）。§13.3.2 说「B3 以上是糊不是焦外、
  与 24 色纪律冲突加剧」，这条告警在这里是**成立的**，裁决权交回给人。
- **退回 k=7 的退路保留**：只改一个常数，C7 会如实变红——这是可复现的对照实验，不是估计。

## 4.1 残差构成：C8 与 C8b 拆成两条

把 depth ≥1000 的立体构件**全藏掉**之后（`Oracle.debugHideAboveDepth(1000, true)`），糊图
（depth 999）盖住了全部贴地层，三个机位的远带残留都是 **0**——这是 C8，守「闭包有没有漏」。
把构件放回来，读到的才是 S-4 的已知残留，这是 C8b。

| 机位 | 坐标 | 远带内容 | C8（藏 ≥1000） | C8b（放回来）px / 簇 / 最长 |
| --- | --- | --- | --- | --- |
| 渡口 | 300,160 | 水面 | 0 px | 471 / 9 / **16.5** |
| 林地 | 200,400 | 树林 + 屋顶（无水） | 0 px | **13,393 / 191 / 88.5** |
| 屋面 | 800,700 | 屋顶 + 煤场（无水） | 0 px | 12,760 / 120 / 72.5 |

**为什么要拆**：C8 原本混了两层——我们控得住的闭包、和我们结构上拿不到的建筑附属物。
混在一起的闸永远红，红了就没有信号。拆开后 C8 是 0，C8b 才有意义。

**档位说明**：用户按渡口单机位拍的 C8b 上限是 600 px / 12 簇 / 18 px，那是按「远带只有
一栋楼的屋顶探进来」估的；无水机位的远带里只要有一整片街景或整栋楼，按像素计的锐边
就是万级——这是 S-4 的结构性后果，不是回归。C8b 因此按三机位**实测最差 + 余量**做棘轮：
**14,000 px / 200 簇 / 96 world px**，只保证「不许悄悄变多」。明细见 OPEN_ISSUES E15。

渡口机位这 471 px 的构成（不剥标签时是 1,489；剥掉 `.setting-region-label` 后是 471，
差 ≈1,018 全是 DOM 标签，不进判据也不进计数）：

471 个像素按 4 邻接连通块是 **9 簇**，前六簇（世界坐标包围盒 `x, y, w, h`）：

| 像素 | 世界包围盒 | 归属 |
| --- | --- | --- |
| 111 | 139.5, 138.5, 16.5, 12.5 | 建筑招牌金框（`buildings.ts` 的 `drawSignIcon`，18×14，描边 16 px，depth ≥ 1000） |
| 99 | 141, 139.5, 14, 10.5 | 同上 |
| 63 | 177.5, 153.5, 12.5, 4.5 | 屋顶构件（≥1000） |
| 57 | 138.5, 138, 8.5, 20.5 | 建筑招牌 |
| 53 | 140.5, 140, 6.5, 10 | 建筑招牌 |
| 53 | 177, 149.5, 14, 2.5 | 屋顶构件 |
| 余 3 簇 | — | 合计 35 px |

- **招牌 ≈320 px**、**屋顶构件 ≈116 px**、其余 35 px；全部落在 world `x 138–191`、`y 138–159`，
  也就是本机位那一栋探进远带的楼（S-4 的结构性残留），没有一处来自闭包里的贴地入口。
- **最长连续锐边 16.5 world px**（水平，屏幕 x 279–301）、次长 **14 world px**（垂直，屏幕 y 277–276 列）。
  16.5 px 来自招牌那条 16 px 金框，14 px 来自屋顶构件。

读数口径三条，都不许省：

- **C7 只量点名窗口，不量整条远带。** 点名窗口里 `?dof=off` >40、on <20、on 的 ≥40 硬边为 0。
- **C8 / C8b 只量剥掉 DOM 标签后的世界层。** 地点标签是 `.setting-region-label`，浏览器里的 DOM 叠加，
  不在 canvas 里、本来就不该按世界层糊，所以截图时临时 `visibility:hidden`，**不进判据也不进计数**。
  C8 先把 depth ≥1000 的立体构件藏掉（`debugHideAboveDepth`），远带内**连续锐边必须 = 0**；
  它守「糊图之上还有没有漏糊的贴地层」。C8b 再把构件放回来，量已知残留
  （像素数 / 连通簇数 / 最长连续段），阈值是实测棘轮，只守「不许悄悄变多」。
  三个机位（渡口 / 林地 / 屋面）各量一遍，最差写进 C8b 与 OPEN_ISSUES E15。
- 两页的**世界时钟对齐到整分钟**再冻：`totalCommands` 是全场景命令和，包含按世界时刻重画的
  渡口灯影与船档期；不对齐时两页会差 8 条，C4 就会把「世界差了几拍」误报成「这一笔多画了东西」。

`?dof=off` 下 `createDofView` 根本不会被调用：没有多出来的 Image、纹理或绘制项。

渲染预算那把闸与 §13.10 的命令上限**不是同一个读数**，别混着报：`test:render-budget` 在本分支通过，
峰值 **33,445 ≤ 33,488**（dengchao 场景的既有天花板）；§13.10 的 `peakCommands` 34,573 是另一把闸。

## 6. 未闭合项

1. **S-4：≥1000 的立体构件不在闭包里。** 建筑 / 摊位 / 立面补绘与人物逐行交错，
   平面糊图结构上盖不到（见 §2）。C8（藏掉 ≥1000）在三个机位都是 0，证明闭包没漏；
   把构件放回来，C8b 的已知残差最差是**林地 13,393 px / 191 簇 / 最长 88.5 world px**，
   渡口只有 471 px / 9 簇 / 16.5 px（招牌金框 ≈320 px + 屋顶构件 ≈116 px + 其余 35 px）。
   也就是说：**远带里有多少 ≥1000 的内容，就有多少锐边**，这是结构性的，不是回归。
   C8b 的阈值因此是从实测最差收下的棘轮（14,000 / 200 / 96），不是可接受线；
   成因、三机位读数与「S-4 未闭合」的定性记在 OPEN_ISSUES E15。
2. **C8 首跑误红一次（已修）**：残差把远带裁切窗最后一行/列（device 1 px 的隔离缝）算成了连续锐边，
   最长报到 31 world px。`residualStats` 现在跳过区域最后一行/列——那是设计上的硬边，不是结构。
3. **S-5 潮位未离散化。** 潮位/倒影不在闭包里，远带水面与灯影保持清晰。
4. **C2（硬件 / SwiftShader 双后端 0 diff）**：本机只有 SwiftShader，留给 CI 两台执行器。
5. **166 张基线**：本树没有基线夹具集（在另一条工作线上），本笔只能从结构上保证默认路径零新增。
