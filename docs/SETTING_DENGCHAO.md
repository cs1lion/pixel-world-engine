# 灯潮界：首版设定集落地范围

原创设定集驱动的第二个世界。入口是 `?world=dengchao`；省略 `?world` 仍进旧镇「莞尔镇」，
旧地图的行为与存档一个字节都不变。

这份文件只回答一件事：**设定手册里的哪些内容真的跑起来了，哪些还没有。**
把配置写进数据不等于玩法做完——下面两栏分开写，就是为了不把前者说成后者。

设定来源：本地设计手册《像素异界设定集：以〈千与千寻〉美术设定为参照》。
本仓只取它的结构、色板与区域语法，不复刻原作的角色、名称或标志性造型。

## 已经跑起来的

### 地图

一张连续的 64×48 户外地图，五个语义区域由数据声明，不是硬编码坐标：

| 区域 | id | 内容 |
| --- | --- | --- |
| 渡口站台 | `ferry` | 石砌码头上的旧站台、候车位置、旧站牌 |
| 浅滩轨道 | `shoal` | 横贯整片浅滩的断续轨道，退潮时才完全露出 |
| 叠浪楼 | `bathhouse` | 楼体外观、门前水口与朱红桥、楼前长灯 |
| 灯街 | `lampstreet` | 十盏街灯、三处摊位、三幅幌布、茶摊与补灯铺 |
| 积尘滩 | `sootbank` | 煤渣地、废弃物堆、蒸汽 |

炉底层只在叠浪楼地下入口（`boiler_annex`）上体现，**没有做室内**。

语义区域与旧的建造分区是两套东西：`region` 管地名与展示，`zone` 管建造许可。
新区域名没有改动旧的分区规则，v3 存档校验也不受影响。

### 世界自己过日子

- 七位居民：「迷路人」在站牌、灯街、浅滩之间认路；渡守「汐」提灯点灯、照看来客、
  拾灯芯；「灯笼头」点亮街灯、点数灯桩；「炉匠」在炉匠铺与炉底入口之间搬炭；
  「沉灯夫人」在镇心沉灯、讲那年的潮；「账房先生」在账房门口核账；
  「洗衣妇」上叠浪楼收衣裳、到滩边晾晒。后五位的**岗位与地点**来自这份文档点名的
  三个名字与叠浪楼的楼层清单，**字面是这一仓起的**（见 `pack.ts` 的注释）。
- 作息点由设定集给出，`routineFor` 是纯函数，同一个存档回放出同一条路线。
- 潮汐是世界自己的时钟（12 分钟一个周期，带确定性抖动），真实影响三件事：
  低地被淹的画面、寻路代价（涉水很慢但仍可走）、以及**作息选择**——
  满潮时避开浅滩，退潮才去轨道与拾荒点。
- 灯油只影响渲染：油尽时人发灰、动作采样放慢到约 3fps。它**不进入**寻路、
  任务结算或任何世界判定；`VillagerSnapshot.lampOil` 是存档 → 渲染的单向读。

### 楼接活

九栋楼里有三栋带 `boundTask`，每种上游活各有一栋常驻铺子：

| 楼 | 活 | accent |
| --- | --- | --- |
| 账房（`ledger_house`） | `writing` | `ink` |
| 灯录阁（`lamp_archive`） | `research` | `pages` |
| 炉匠铺（`soot_forge`） | `code` | `smoke` |

在此之前六栋楼的 `boundTask` 全是 `null`，上游每一条活都被拒，回执说「这座镇子
没有接 code 的铺子」。三栋落地后，一条活会真的派到人、走进那扇门、做完、交出来
——`test/pack-venue.test.ts` 是这条链的端到端证据（喂一条真实上游的 code 活，
断言 `task.delivered` 带着 `taskKind === 'code'` 落到炉匠铺）。

### 传说与碑

- 记忆层把「一件事被五个人讲满三天」的信念立成传说（`legendHolders = 5`、
  `legendDays = 3`）。实测（7 人 9 楼、1000ms 拍、8 个世界日）一共立起 28 条：
  第 4 天关账时 14 条，第 5、6、7 天再各立 5、2、7 条——新闲话攒够人数就再立一批。
  这个数分两次量的：同一份代码**不登记地标**时是 30 条（第 4 天 14 条），登记了那
  22 个地标之后降到 28——地标也是听众，同一句闲话被更多单位分摊，够五人讲满三天
  的反而少了。上一版（地点还在说话、也没有地标）量到的 27 条，与这两个数都不是
  同一种世界，别拿它当对照。
- 立碑要过两道：`legendImportanceFloor = 0.4` 之上的大事各立各的碑；够不着门槛的
  闲话**同一天同一个地点并成一块**（同地有大事那天不并，第二天再兜底）。实测把门槛
  压到 0（即「收束之前」）是 59 条、第 4 天 38 条——灯潮界今天的事件全是
  `routine_done`（hint 0.35），所以出碑走的全是兜底那条路，门槛只负责分栏。
- `legend.formed` 进镇志（服务端 `server/memory/snapshot.py` 的「传说」一节）。
- 碑立在镇心旁（`scenery: stele`），点它开 `#stele-panel`：一块碑一行讲法、
  「第 N 天立」「N 人在讲」，最多摆 `STELE_MAX_LINES` 条，被截断时补一行
  「还有 N 块」。开局空态照实说「要等一件事被五个人讲满三天」，两个数字从
  `DEFAULT_MEMORY_CONFIG` 取，不手写。
- 中文不进 canvas：碑上不刻字，字全在 DOM 面板里。

### 墙上的痕迹与楼的名字

- **痕迹上屏走 `ExpressionHint`，不直接读记忆库**（补充设计 §10）。记忆层把
  痕迹交成一张单子（`world/memory/hints.ts` 的 `placeHints`），渲染层只画单子
  上的东西（`render/decal.ts`）。单子的来源与「从痕迹推断」是同一道闸
  （`traceExposedLayers`，一栋楼最多露出三道，按 `intensity × visibility` 排）
  ——同一道闸的两种读法，不是两条各算各的路。
- **风化在画面上看得见**：每道痕迹的 alpha 就是它的 `visibility`（协议 §11
  「风化只降可见度」）。浓淡另由 `intensity` 决定：两道同样旧的痕迹，重的那道
  更浓，不会更清楚。
- **地名演变**（协议 §11）：一个地点**第一条活着的传说**里最重的那件事，若 kind
  在 `toponym.ts` 的 `EPITHETS` 表里（`milestone` / `celebration` / `conflict`）
  且重量够得着 `renameImportanceFloor = 0.6`，这个地点就换一次名：`原名·称号`。
  一个地点**只改一次**——改两次名字，历史链读起来就是世界说话不算数。
  `conflict`（0.55）在表里但够不着门槛，所以「打架不该给镇子改名」是一条能验的话。
- 称号那三个字面（立事 / 张灯 / 争口）**是本仓起的**，与「灯潮界」「账房先生」
  同性质：只取参考手册的结构、色板与区域语法，不复刻原作的角色、名称或造型。
- **点楼开 `#building-panel`**，四行四个来源，一个都不新造：名字（含称号）与
  「第 N 天因某事改名」的历史链读 `MemoryRuntime` 的 `placeNames`，接什么活读
  `boundTask`，此刻在干什么读工位快照，墙上留着什么读 `placeHints`——与画在墙上
  的那一份同源。楼被拆掉时面板自己收起；改名落地时开着的那一块会刷新一次。
- `toponym.changed` 是 `MemoryEventKind` 十七种里**第一个有接收方**的：发出方在
  `MemoryWorld` 的 `maybeRename`，接收方是场景里那块楼面板。它不进镇志——改名是
  记忆层的读法，不是世界事件。
- **今天这套设定集里看得见痕迹，但还改不了名。** 实测（7 人 9 楼、1000ms 拍、
  8 个世界日）：`trace.added` 发了 **267** 次，全部是 `worn_path`（走出来的路），
  落在 **3 栋楼 + 15 个地标**上；`EPITHETS` 表里的三种一件都没发生，所以
  「还没改过名。」照旧是实况。原因是这里的事实只有 `routine_done`（334 条）与
  `tide_turn`（48 条）两种，而 `tide_turn` 不在 `FOOTFALL_KINDS` 里——潮水不走人，
  它冲不出路来。
- **痕迹的来路**：同一地点、同一 kind 的事**重复到第 4 次**（`recurrence >= 3`，
  第 1 次不算重复）踩出一道 `worn_path`，强度 `recurrence / 10`，同层合并取高。
  第一次踩出来是**世界时间第 12.5 小时**（第 1 天的 `place:36,29`），叠浪楼是第 17 小时。
- **落点归谁**：作息落点 2 格内有楼门就记在那栋楼上（`footfallPlace`，欧氏距离、
  同距取 id 小的），否则记成 `place:x,y` 并**登记成一个地标 Holder**——不登记的话
  痕迹落在格子上没有主人，谁也读不到、也画不出来。灯潮界的 27 个作息落点里
  5 个归楼（叠浪楼 ×2、迎灯舍、炉匠铺、账房），其余 22 个登记成地标。
- **地标上的痕迹画在地上**（`drawGroundDecals`，深度 -5，压在地形 -10 之上、
  一切立着的东西之下）；楼上的仍画在墙上。同一个 `traceId` 永远落在同一处，
  alpha 就是 `visibility`——地标也一样。
- **痕迹的颜色从设定集的色板来**（2026-11-02 修）。`drawGroundDecals` 与
  `drawDecal` 早先写死全局 `WORLD`，于是灯潮界的地上和墙上一直画着莞尔镇的
  石头色（`#3e433f`，而这一格的地形石头是 `#52666a`，两种石头色同屏）。现在
  `palette` 是**必填入参**，漏传是 `tsc` 的一条 `TS2554`，不是悄悄退回莞尔镇。
  修对之后露出第二件事：带子用 `stone` 槽，而石头地的底色正是 `palette.stone`
  ——对比度 **1.00**，一格都看不见。所以 `bandFace` 退一档到 `plaza`（撞了再退
  `trim`），判据是「不许与脚下同值」，换设定集不用重新量。
  像素证据是同一格（`place:19,15`，石头地）的 48×48 裁片，同格、同镜头、
  `?time=noon`，但**是两次运行**——所以只能比带子本身，不能整张图逐像素比
  （村民与灯柱的位置两次不同）。修前 `#3e433f` **184** 个、`#4a4f42` **8** 个，
  修后两个都是 **0**；带子在两次里都落在第 22 行、灯柱右侧第 20–39 列，
  颜色从 `#3e433f` 变成 `#7d8984`（对比度 1.67）。
- **地标不说话，只听。** 地点 Holder 收得到传言（覆盖率与传说的分母里有它），
  但 `spreadCandidates` 只放人物当说话人：协议 §3 把「亲历与听说」与「在此发生过
  的事」分得很清。同一份代码、同一个 8 日世界，只把这道闸拆掉：村民信念从 **330**
  条涨到 **591** 条，其中 **261** 条（44%）的前手是楼；闸在，是 **0** 条。
- 「走的人多了就是路」那条的阈值 3 原先数的是**已有的痕迹条数**（`recurrence`），
  而不是经过次数——没有前两道别的痕迹，它永远轮不到自己。这一版改成数**事件**，
  2026-11-01 修好；`test/consequence-kinds.test.ts` 钉住「潮水反复冲刷不踩路」。

### 点村民：她记得什么，从谁听来

- 点人开 `#villager-panel`，三行「记得的事」来自 `recallForDialogue`（`commit: false`，
  看一眼不改世界）。每行后面跟出处：亲历、读到、推断的照实说；听来的写「从谁听来」，
  名字从 `sourceChain` 尾节反查——链的构造保证最后一节就是直接前手。查不到人就照实说
  「从一个不在这张图上的人听来」，不显示裸 id。
- **今天这个出处仍然几乎总是「镇上的人都这么说」。** 实测（7 人 9 楼、1000ms 拍、
  8 个世界日）：七人的记忆库里一共 **5** 条带前手的听来记忆（炉匠 1 / 沉灯夫人 1 /
  账房先生 2 / 洗衣妇 1；迷路人与汐 0），而七人面板的前三行一共 **21** 条，
  全部是碑文（`sourceChain` 为空，读作「镇上的人都这么说」），一条听来的都没排上。
  所以今天在浏览器里看得见「大家都这么说」，看不见「从谁听来」：读出口是通的、有单测，
  只是这个世界的排序轮不到它。要让它排上来，得先有比碑文更值得先讲的事，或者改排序
  ——后者是另一件事。
- 听来的这 5 条**前手全是人**，没有一条是一栋楼：这是「地点不说话」那道闸的直接
  证据。同一批测量里，七人记忆库的来源分布是亲历 79 / 听来 115 / 从痕迹推断 27。
- 「从痕迹推断」那 27 条现在真的进得来：`lookAtTraces` 每格每人每天一次，
  地标和楼一样走这道门，推出来的讲法是「最近有人频繁往返于这条路线」（`habit`）。

### 命令闭环

一句话仍然只能走既有协议：规则优先，认不出才问模型，模型输出过白名单。
灯潮界把自己的模板表随请求发给服务端，所以模型看到的是这一张图的十种模板。

- 唯一开局不落位的模板是**候车亭**（`waiting_shelter`）。世界拒绝「同一种铺子建第二栋」，
  如果九个模板全落位，`building.add` 在这张图上就永远只能被拒，那句话等于摆设。
- `npm run test:live` 会对默认世界与灯潮界各跑一遍真实 HTTP 建造与拒绝，
  包括「发出去的是这一套设定集的模板表」「两套存档槽互不覆盖」。

### 存档

每套设定集一个 `localStorage` 槽（灯潮界是 `dengchao.pixel-world.save.v1`）。
清档、坏档备份、导入导出都绑定同一个槽，在灯潮界清档不会碰掉旧世界的存档。
存档 schema 是当前的 v5（以 `world-client/src/world/save.ts` 的 `CURRENT_SCHEMA_VERSION` 为准），<!-- claim: save-schema-version=5 -->
世界 id 不写进 JSON。

## 还没有做的

设定手册里存在、但这版**没有实现**的东西。列在这里是为了不让人把上面的完成度当成完整游戏：

- 叠浪楼室内八层（账房 / 宴席 / 浴池 / 大堂 / 洗衣仓 / 炉底层）与屋顶庭院、天梯。
  居民会走到这些楼层的门口与镇心，但**楼里没有可进入的室内空间**。
- 契约系统、名牌抵押、交易与商店。
- 清污小游戏与积尘滩的「暗面遭遇」。
- 三幕剧情、折返时场景变化的叙事、音乐与音效。
- 可操控主角；这版只有七位自主居民。
- 设定手册里的「区域瓦片清单」（渡口 24 种、灯街 32 种 …）没有逐条实现，
  用的是 24 色预算内的现有地形材质与构件。

## 数据在哪

```text
world-client/src/settings/dengchao/pack.ts   地图、区域、模板、落位、居民作息、构件
world-client/src/settings/load.ts            装载与校验（越界、未知色、重复落位都在这里拒）
world-client/src/settings/types.ts           设定集的外部形状
world-client/src/settings/index.ts           设定集选择与装配
world-client/src/world/memory/stele.ts       碑的读侧：排序、截断常量、淡去标记
world-client/src/world/memory/hints.ts       交给表现层的单子：哪些痕迹该画出来
world-client/src/world/memory/toponym.ts     改名判据：称号表与门槛
world-client/src/render/decal.ts             痕迹画在墙上的哪一处、画几笔
world-client/src/ui/building-panel.ts        楼面板：名字、活、状态、痕迹、历史链
```

设定集是数据，不是代码入口：`loadSettingPack` 先校验再编译成已有的网格与蓝图，
不通过就抛错、不带着半个世界开工。换一套设定集不需要动 `Simulation`。
