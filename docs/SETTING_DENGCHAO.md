# 灯潮界：首版设定集落地范围

原创设定集驱动的第二个世界。入口是 `?world=dengchao`；省略 `?world` 仍进旧镇「莞尔镇」，
旧地图的行为与存档一个字节都不变。

这份文件只回答一件事：**设定手册里的哪些内容真的跑起来了，哪些还没有。**
把配置写进数据不等于玩法做完——下面两栏分开写，就是为了不把前者说成后者。

设定来源：本地设计手册《像素异界设定集：以〈千与千寻〉美术设定为参照》。
本仓只取它的结构、色板与区域语法，不复刻原作的角色、名称或标志性造型。

## 已经跑起来的

### 地图

一张连续的 64×48 户外地图，五个语义区域由数据声明，不是硬编码坐标：

| 区域 | id | 内容 |
| --- | --- | --- |
| 渡口站台 | `ferry` | 石砌码头上的旧站台、候车位置、旧站牌 |
| 浅滩轨道 | `shoal` | 横贯整片浅滩的断续轨道，退潮时才完全露出 |
| 叠浪楼 | `bathhouse` | 楼体外观、门前水口与朱红桥、楼前长灯 |
| 灯街 | `lampstreet` | 十盏街灯、三处摊位、三幅幌布、茶摊与补灯铺 |
| 积尘滩 | `sootbank` | 煤渣地、废弃物堆、蒸汽 |

炉底层只在叠浪楼地下入口（`boiler_annex`）上体现，**没有做室内**。

语义区域与旧的建造分区是两套东西：`region` 管地名与展示，`zone` 管建造许可。
新区域名没有改动旧的分区规则，v3 存档校验也不受影响。

### 世界自己过日子

- 两位居民：「迷路人」在站牌、灯街、浅滩之间认路；渡守「汐」提灯点灯、照看来客、拾灯芯。
- 作息点由设定集给出，`routineFor` 是纯函数，同一个存档回放出同一条路线。
- 潮汐是世界自己的时钟（12 分钟一个周期，带确定性抖动），真实影响三件事：
  低地被淹的画面、寻路代价（涉水很慢但仍可走）、以及**作息选择**——
  满潮时避开浅滩，退潮才去轨道与拾荒点。
- 灯油只影响渲染：油尽时人发灰、动作采样放慢到约 3fps。它**不进入**寻路、
  任务结算或任何世界判定；`VillagerSnapshot.lampOil` 是存档 → 渲染的单向读。

### 命令闭环

一句话仍然只能走既有协议：规则优先，认不出才问模型，模型输出过白名单。
灯潮界把自己的模板表随请求发给服务端，所以模型看到的是这一张图的七种模板。

- 唯一开局不落位的模板是**候车亭**（`waiting_shelter`）。世界拒绝「同一种铺子建第二栋」，
  如果六个模板全落位，`building.add` 在这张图上就永远只能被拒，那句话等于摆设。
- `npm run test:live` 会对默认世界与灯潮界各跑一遍真实 HTTP 建造与拒绝，
  包括「发出去的是这一套设定集的模板表」「两套存档槽互不覆盖」。

### 存档

每套设定集一个 `localStorage` 槽（灯潮界是 `dengchao.pixel-world.save.v1`）。
清档、坏档备份、导入导出都绑定同一个槽，在灯潮界清档不会碰掉旧世界的存档。
存档 schema 仍是冻结的 v3，世界 id 不写进 JSON。

## 还没有做的

设定手册里存在、但这版**没有实现**的东西。列在这里是为了不让人把上面的完成度当成完整游戏：

- 叠浪楼室内八层（账房 / 宴席 / 浴池 / 大堂 / 洗衣仓 / 炉底层）与屋顶庭院、天梯。
- 契约系统、名牌抵押、交易与商店。
- 清污小游戏与积尘滩的「暗面遭遇」。
- 三幕剧情、折返时场景变化的叙事、记忆系统、音乐与音效。
- 更多居民（灯笼头、炉匠、沉灯夫人等）与多角色协同。
- 可操控主角；这版只有两位自主居民。
- 设定手册里的「区域瓦片清单」（渡口 24 种、灯街 32 种 …）没有逐条实现，
  用的是 24 色预算内的现有地形材质与构件。

## 数据在哪

```text
world-client/src/settings/dengchao/pack.ts   地图、区域、模板、落位、居民作息、构件
world-client/src/settings/load.ts            装载与校验（越界、未知色、重复落位都在这里拒）
world-client/src/settings/types.ts           设定集的外部形状
world-client/src/settings/index.ts           设定集选择与装配
```

设定集是数据，不是代码入口：`loadSettingPack` 先校验再编译成已有的网格与蓝图，
不通过就抛错、不带着半个世界开工。换一套设定集不需要动 `Simulation`。
