# ADR：`building.add` 的 `at` 可以省略——服务端比它要对齐的那份协议更严

- 状态：已接受
- 日期：2026-10-27
- 关联票据：#16
- 上游：`docs/INTENT_EXPERIMENT.md`（55 条实测）

## 背景

#16 要回答的是「真实模型面对真实 prompt 时，会不会只输出白名单内的命令」。
55 条跑完，合法命令 26 条里过了 14 条。逐条看那 12 条失败，分成两堆：

- **5 条 `building.remove`**（「把抄书斋拆了吧」「那栋楼不要了」）。实验故意传
  `context=None`，模型看不到「已经建了：……instanceId=……」那一段，没有 id 可抄。
  那是**从严设置的产物，不是模型的错**——线上客户端两样都发。
- **5 条 `building.add`**（「建个工坊」「给我整个新铺子」「这儿再盖一座炼码工坊」
  「帮我盖个资料馆」）。共同点：**用户没说地点**。

后一堆是要修的。而模型答 `unknown` 不是它笨：提示词写着 `at` 必填，
用户没给坐标，它只能编一个数——而纪律第 4 条正是「越界就照实输出，
不要自己改数」。编一个坐标与之直接冲突，于是它选了 unknown。

## 决策

`building.add` 的 `at` 改为**可省略**。省略时命令里就没有这个键，
`command_to_intent` 映射成 `at: null`，与 `miracle.spawn` 同一处理。

提示词同步说明：用户没说地点就别填，世界自己挑空地方；用户说了坐标才填。

## 理由

**这不是放宽规则，是对齐。** #16 的交付项写着「形状对齐上面那份已冻结的线协议」。
而客户端的 build 意图一直就是 `at: GridPoint | null`：

- `world-client/src/world/intent-schema.ts` 的 `readPoint(undefined)` 回 `null`；
- `simulation.ts` 收到 build 时写 `at: intent.at ?? undefined`；
- `setup.ts` 的 `placeBlueprint` 在 `at === undefined` 时走 `grid.findBestSlot`，
  自动选最靠近锚点的合规空地。

**整条客户端链路本来就把「没有坐标」当「随地」在处理。** 只有服务端的
`_building_add` 要求 `at` 必填——它比它要对齐的那份协议更严，而严在这儿
没有换来任何安全，只换来 5 条 unknown。

**不能让模型挑地方。** 模型不知道哪儿空着：它挑的那个数要么被 `checkPlacement`
拒，要么落在别人家门口。省略 `at` 的意思是「随地」，挑哪儿是世界的事——
世界有 `findBestSlot`，模型没有地图。这与「坐标越界照旧查」不矛盾：
带了坐标一分钟都没放松，只是没带时不再逼一个。

**原来那条 `test_建楼缺坐标被拒` 的前提已不成立。** 它的理由是「选址是世界的活，
但那是 #6 之后的事」。`placeBlueprint` 的自动选址早就在了——不是将要实现，
是已经实现。测试钉的是一个过时的事实，所以连它一起改，而不是留着它红。

## 后果

- 好：「建个工坊」这类不说地点的话不再被迫答 unknown。5/12 的缺口直接对着它。
- 好：服务端与冻结线协议对齐。`docs/intent.sample.json` 加了一条
  「造物不带坐标」的冻结样例，客户端 `intent-contract.test.ts` 拿同一条
  反向验过——两边同时认，改协议时两边同时红。
- 代价：世界多了一条「自己挑地方」的路径要负责。它本来就有
  （`placeBlueprint` 的 `at === undefined` 分支），但此前从没有意图能走到那儿；
  现在意图能走到了，那条路径从此有人走，就得一直对。
- **已验**：55 条重跑过。严格模式下合法命令接受率 14/26 → 21/26，
  5 条 `building.add` 全过；带上客户端现状那一侧是 24/26。
  两个数字都在 `docs/INTENT_EXPERIMENT.md` 里，各自的备注行写着是哪一侧。

## 备选

| 方案 | 为什么没选 |
| --- | --- |
| 让模型编一个坐标 | 它没有地图，编出来的数要么被拒、要么落在别人家门口。而且这与纪律第 4 条「不要自己改数」直接冲突 |
| 服务端也要求 `at`，但在提示词里教模型「用户没说就随便给一个」 | 同上，只是把锅从校验器挪到提示词。随便一个坐标仍然会被拒，用户看到的是「听懂了」然后被拒 |
| 客户端先放宽，服务端维持严格 | 两边说不同的话。冻结线协议的意义就在于两边必须是同一句 |
| 加一条 `building.addAnywhere` 命令 | 六条命令已经够记。「随地」是 `building.add` 的一种参数形状，不是一件不同的事 |
