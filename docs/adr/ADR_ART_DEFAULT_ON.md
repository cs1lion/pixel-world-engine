# ADR_ART_DEFAULT_ON：位图素材转默认开，`?art=0` 才是关

- status: aligned
- verified_at: 2026-11-10
- verified_by: agent（用户「风格就按设定集，我要的是表现力，为此你可以调整技术栈」→ 5 步路线第 3 步）
- evidence: `world-client/src/render/art-assets.ts`, `world-client/scripts/check-art-assets.mjs`, `world-client/test/art-building-scale.test.ts`, `docs/evidence/art-pipeline/before-after-world.png`

## 1. 问题

素材已经长到 19 件（10 建筑 + 2 村民 + 7 布景），观感对比图也做过，
但开关 `?art=1` **默认关闭**。结果是：谁都不加参数，看到的就是程序化绘制——
这批素材在正式体验里等于不存在。用户要的「表现力」一直停在实验室里。

## 2. 决策

- **默认开。`?art=0` 是唯一的关法**，写作 `params.get('art') !== '0'`。
  它是排障与像素基线比对用的退路，不是日常状态；认不得的值（`art=true`、
  打错字）按默认（开）算——写错一个字不该让画面悄悄退回程序化绘制。
- **缺一件素材不等于缺一块画面**：`hasArt` 只看纹理装没装上，
  清单里没有这一件（莞尔镇、没生成过的楼）就落回程序化路径。
  所以「默认开」不要求素材全覆盖，只要求缺的那件不崩。
- **装载冒烟加一跑**：`check-art-assets.mjs` 原来只跑 `art=1` 与 `art=0`，
  现在多跑一次**不带任何 art 参数**，断言它照样请求 `manifest.json` 与全部
  PNG。没有这一跑，「默认开」就没有任何闸门在看。

## 3. 不在范围

- 不改素材本身，不动 `ART_SCALE`、缩放兜底、抠底参数。
- 不删程序化绘制路径：`?art=0` 必须仍然画出完整的一个世界。
- 不动渲染预算门槛。实测硬闸门 3 项通过，绘制指令债务 0 条 / 额度 3488 条。

## 4. 代价与已知边界

- **像素基线从此默认不是「程序化那套」**。要逐字节比对旧基线，必须显式
  `?art=0`。这条写进脚本与注释里，否则下一个人会以为画面自己变了。
- **首屏多 19 个 PNG 请求**（每张都很小，`manifest.json` 一件一次）。
  渲染预算冒烟里前台帧率 53–60，与关闭时同档。
- **程序化路径的冒烟必须显式 `?art=0`**。`check-building-bake.mjs` 守的是
  「每栋每层都烘焙了」，位图楼整栋换成一张生图、根本不走 `bakeLayer`，
  于是它默认会在 9 栋楼上全红（PR #38 的浏览器 job 就是这么红的）。
  这不是回归，是两条渲染路径；现在那个脚本显式带 `art=0`，
  位图那条路由 `check-art-assets.mjs` 守。
- **位图层没有色板闸门**（`ADR_ART_PALETTE_DECISION` 的已知代价）：
  默认开等于让不受色板预算约束的那一层成为日常画面，这是有意接受的取舍。

## 5. 验证

- 装载冒烟（`npm run test:art-assets`，真浏览器）：
  `art=1` 清单 19 件全请求且 200；**默认 19 张**；`art=0` 零 `/assets/` 请求；
  三跑无 pageerror。
- 渲染预算冒烟：硬闸门 3 项通过，绘制指令债务 0 条。
- 相位冒烟：四刻可辨 40 项通过（默认参数下跑，即这批素材在用的那套画面）。
  全跑 6m13s——四刻各等村民落定约 26s，是既有等待，不是这次改动引入的。
- `test/art-building-scale.test.ts` 6/6：新增一条钉开关判据
  （空查询串为真、`art=0` 为假、认不得的值按默认）。
