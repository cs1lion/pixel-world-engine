# ADR：尺度类改动必须同时给常量读数与像素扫描读数

- evidence: `world-client/src/render/setting-scale.ts`, `world-client/scripts/check-setting-scale.mjs`, `world-client/test/setting-scale.test.ts`

- 状态：已接受
- 日期：2026-11-04
- 关联：`docs/SETTING_DENGCHAO.md`（灯潮界尺度）、`eval/screens/setting-scale.png`（对照图）

## 背景

尺度改动出过一次「常量对、画面错」：

- `drawShopfront` 里把墙顶写成 `top = -SHOPFRONT_TOP`（绝对值，本该是 `y - SHOPFRONT_TOP`），
  整排店面被画到世界原点附近、一像素也不在镜头里；
- 常量读数照样是 **48**（`SHOPFRONT_WALL_H + SHOPFRONT_STONE_H`），
- 逐像素扫描只量到 **6px**（那一列只剩别的构件）。

如果只看常量，这条改动会被判「通过」。**常量是绘制意图，扫描是渲染结果，两者不是同一件事。**

## 决策

凡是尺度类改动（墙高、柱高、灯体离地、人物与构件比例），回执**必须同时给出两个来源的读数**：

1. **常量读数**：渲染实际使用的那几个像素数（必须来自渲染层同一份常量，不许在回执里另抄一份）；
2. **像素扫描读数**：同一机位、同一冻结帧的截图里逐像素量出来的长度。

**两者不一致即为失败**，不许用「常量是对的」放过画面。`scripts/check-setting-scale.mjs`
用 `[扫描自洽]` 判红退出，并把「相等/不等」交给 `annotateEquality` 生成——只有真的
相等才写 `（= 墙高 48）`，不相等一律写 `（≠ 墙高：读数…期望…差…）`。

扫描口径：

- 扫描列要选在该构件上**可量的一段**：店面选左木框，灯柱选柱脚到灯体下沿那一截；
- 墙面不是一整块纯色：`c.timber` 的木纹刺（1×2px，正好压在这个扫描列上）与板缝会
  把同色段打断（`2589366` 的材质升级后，最长的第一段只有 13px）。因此墙高按
  **允许 ≤3 世界像素断点的连续段**量到檐口下沿（`wallBandH`）；单纯连续段
  （`frameH`）只作辅助读数，必须写明「不等于墙高」，不许再标 `= 墙高`；
- 不要选会被格窗、门、招牌、角色、灯光覆盖的列；
- 1px 的口径差要写明（例：旧画法把灯体底下的 `ink` 衬线画在灯体外，注释里的 25
  实际净空是 24；新画法把衬线收进灯体最后一格，43 就是净空）。

**政策常数：`WALL_BAND_MAX_GAP_WX = 3`（世界像素）**。它为什么是 3：`2589366`
之后，木框扫描列上的实测断点共 4 处、每处 2 世界像素宽（`c.timber` 木纹刺 1×2px，
正压在 `x+1`），所以「≤3」只容得下这类细刺，容不下真正的结构断裂（8px 以上的
错位/缺口）。放宽到 6 会把「结构断了」吞成「墙高没变」——将来任何放宽都必须按
政策常数记账（理由 + 同帧实测对照 + 谁批的），不许顺手改。

**量法的适用边界（2026-11-08 实测）**：扫描列固定在店面左木框（`x+1`），而窗从
`x+5` 起、窄立面的门从 `x+width-18` 起、竖招牌在 `x+width-7`、挂灯在檐下幔脚，
都不落在这一列——所以窗/门/挂灯不会打断它。同一冻结帧对 `shopfront_west`(12,27)、
`shopfront_mid`(36,27)、`shopfront_east`(48,27) 三家各量一次，`wallBandH` 都是 48
（`frameH` 分别 12/13/12，差异只来自木刺位置）。边界：本口径只覆盖 `shopfront`
这一种 48px 窄立面；`shopfront_gable`（y=23，落地线不同、带圆窗）不在本闸门的
扫描范围内，要用得另定扫描行与列。若将来把窗/门挪到左木框列，≤3 的断点会被
打破、闸门判红——这是期望的失败方向，不要靠放宽常数把它变绿。

## 理由

- 尺度是「画面上的长度」，只有像素能证明它真的长在了该长的位置；常量只能证明数字被算对了。
- 遮挡分层、光池这类改动也同一个道理：可测的读数要落在**渲染产物**上，不是落在意图上。

## 后果

- 落地位：`scripts/check-setting-scale.mjs` 每张图都同时打「常量 / 墙高扫描 /
  连续段」三行，墙高扫描与常量不一致时 `[扫描自洽]` 判红；
  `test/setting-scale.test.ts` 钉住常量之间的关系；扫描钉住画面。
- 读数来源必须诚实：`scripts/check-setting-scale.mjs` 拿不到
  `window.Oracle.debugSettingScale` 实测值时，打印 `[判据前提不成立]` 并**非 0 退出**，
  不退回改前基线常量继续判定——否则「通过」可能只是基线在和自己比。「环境没有这个
  钩子」与「钩子在但读数非法」分开报，后者带实际返回值。
- **消费方按用途分开（2026-11-08 修正）**：基线常量不是读数，但「要不要判红」取决于
  这份数被谁用。
  - **数值消费**（做差、容差判定、任何进入判据的地方）一律走
    `scripts/lib/setting-scale-probe.mjs` 的 `assertMeasuredReading`：来源不是实测就抛
    `[判据前提不成立] 读数非法`，基线常量**硬红**。
  - **仅供人看的并排图**走同模块的 `readShotForComposite`：改前那一拍允许用基线常量，
    但必须同时满足两条——该 JSON 的 `metrics` 为 `null` 且自报基线来源；渲染出来的图上
    必须有可见标注「改前为基线常量、非实测、未参与判定」。改后那一拍必须是实测。
    这样人能看对比，机器拿不到可做差的东西。
- `SCALE_LABEL=before` 的例外**锁在 JSON 里**，不只靠控制台喊一句：该跑落盘的
  `setting-scale-before.json` 必须同时满足 `"metrics": null`、
  `"metricsSource": "改前基线常量（非实测）"`、`"metricsFromBaselineConstant": true`。
  反例见 `test/check-setting-scale-probe.test.ts`（同一份基线 JSON：喂数值比较必须抛；
  走并排图必须成功且带标注）与 `test/fixtures/setting-scale-hook-probe.mjs`。
- 反例脚本的运行口径：`test/fixtures/setting-scale-hook-probe.mjs` 依赖浏览器，
  **不进 `npm test`**；由改动本脚本或其读数口径的人，在收工前于本工作树手动跑
  `node test/fixtures/setting-scale-hook-probe.mjs`（自带桩页，不要求 vite、不读基线目录）。
  判绿口径：5 条全 PASS 且末尾打印「全部通过」——无钩子 exit 1、非法值 exit 1、
  合法值 exit 0、无钩子 + 改前声明 exit 0、改前基线常量 + 并排图 exit 0 且打印
  「并排图标注：改前为基线常量、非实测、未参与判定」。
- 2026-11-08 重拍了 `eval/screens/setting-scale-after.{png,json}`：五个尺度常量与
  `metrics` 五个值均**未变**（`shopfrontH 48` 等），但扫描读数与渲染统计随当期构建变化
  （连续段 `frameH 48→13`、`stoneH 4→3`、`totalCommands 12363→30021`、
  `graphicsObjects 46→155`），图像非逐字节相同。查清后确认**旧基线出自另一个构建**
  （`2194c52`，落后 HEAD 350 个提交）：48→13 是 `2589366` 的木纹刺（1×2px `c.timber`
  正压在扫描列上）打断了连续涂装，`stoneH 4→3` 是同一提交在石脚顶压的 1px `plaza`
  受光边，12363→30021 是 `renderStats` 换成递归口径——都不是「来源字段过期」。
  按新口径（允许 ≤3 世界像素断点）重测同一帧：墙高 48（= 常量 48），旧 PNG 用新旧
  两种口径都是 48。完整调查见 `docs/OPEN_ISSUES.md` 的 E14、E10；旧 `after` 不再用于
  任何比较。此次**未**重拍 `before`，它仍是基线常量口径；并排图按上面的「仅供人看」
  路径合成，图上带标注。
- 「改前 / 改后」必须是同一机位、同一冻结帧、只差尺度这一件事；改前那一拍要先
  `git stash` 掉 `src/` 的改动，再拍 `before`，恢复后拍 `after`。
- 这条不替代别的闸门（预算、调色板、单测），只补上「尺度类改动」这一格的证据口径。

## 备选

| 方案 | 为什么没选 |
| --- | --- |
| 只给常量读数 | 就是上面那次失败：常量 48、画面在原点 |
| 只给截图，不放常数 | 截图读不出「该是多少」，没法判断是画错还是设计就是如此 |
| 用单测钉像素期望值 | 像素断言脆、改画法就红；扫描 + 人工对照图更稳 |
