# ADR 候选：暖中性两档（L\*≈45 / L\*≈58）要不要进 24 色预算

- status: **candidate（未决，等 owner 决策）**
- verified_at: 2026-11-07
- verified_by: agent，按证据整理，未获授权实施
- evidence: `world-client/src/world/palette-data.ts`、`world-client/scripts/audit-palette.mjs`、`world-client/test/palette-budget.test.ts`、`world-client/src/settings/load.ts`、`docs/adr/ADR_PALETTE_24.md`、`docs/evidence/palette-threshold/README.md`、`docs/investigations/P1_SHORE_ROOTCAUSE.md`

> 本文只写证据与代价，**不替 owner 做决定**。没有实施任何改动：`pack.ts` 未改、预算未改、`audit-palette` 的 `BUDGET` 未改。

## 背景

P1 岸线带的白天场景（参考页 67 上部第 3 格）需要「湿泥 → 干泥 → 沙」三段可辨的暖中性色阶。现有 24 色里没有这组；石板段与草地段在 4× 下分别读成「浅边 + 深带」和「几乎看不见」（读数见 `P1_SHORE_ROOTCAUSE.md` §1/§2）。

本候选只回答一个问题：

> 为了让白天暖泥岸有「湿 / 干 / 沙」三档，是否把世界层预算从 24 扩到 26，新增两档暖中性色？

## 证据（实测）

### 1. 24 的预算来源无法复核

- 24 硬编码在四处：`audit-palette.mjs`（`BUDGET.world` + `PROPOSED_WORLD`）、`palette-budget.test.ts`（`WORLD_BUDGET` / `UNION_BUDGET` / `PROPOSED_WORLD`）、`settings/load.ts`（24 槽闭集，注释「加一个就要走 ADR」）、`ADR_PALETTE_24.md` 与 `docs/SPEC_V2.md` §4.2。
- `ADR_PALETTE_24.md` 是 2026-10-27 的**补记**，它要补的那份文档从未存在；「2026-10-21 用户批准」只出现在随代码进入仓的文件头，仓内无法复核。
- 能证的只有「24 = 16 结构性深色 + 8 语义色」；**不能证「为什么停在第 24 个」**。这条是本次讨论的约束事实，不是反对理由。

### 2. 没有免费槽位

- 修好审计误报后（`feat/palette-audit-fix@3228fa5`），24 个 WORLD 槽全部有静态读点（24/24，refs 831，`overBudget 0`）。
- 「未引用」只剩 `TERRAIN_SPECK` 的 5 个别名项；`src/`、`test/`、`scripts/` 无读点，属 dead data，不是可回收的槽。
- 结论：**不存在「把未用色换掉」的免费路径**；腾槽必须改有读点的 token（会连带树边、轨道、农田、屋顶等构件）。

### 3. 暖中性低彩度三档：现有 0 组

灯潮界实际值（L\* / 相邻 ΔL\* / 相邻 ΔE2000）：

| 组 | 三档 | L\* | ΔL\* | ΔE2000 | 为什么不能用 / 能用到哪 |
|---|---|---|---|---|---|
| 冷灰中性 | `soil #202b35` → `farm #3d5154` → `stone #52666a` | 16.9 / 33.0 / 41.7 | 16.0 / 8.8 | 13.58 / 7.48 | **可用**；但它是冷灰（h 212–258），只能当夜岸/湿地，不是白天暖泥 |
| 暖砖红 | `timber #7c4a40` → `terracotta #a4483d` → `ember #bf5441` | 37.0 / 42.6 / 49.3 | 5.5 / 6.7 | 9.24 / 7.12 | **不可用**；彩度 C 25→53，是砖红/陶土，不是泥/沙 |
| 亮暖平铺 | `plaster #b9b294` → `trim #dfbd7a` | 72.4 / 78.2 | 5.7 | 11.92 | 只能当「沙」；不能当湿/干泥（太亮） |

缺的两档：**L\*≈45、L\*≈58**，色相约 60–90°、彩度 C 10–20（暖中性）。现有色在 L\* 33 与 72 之间是空的：`farm` 到 `plaster` 一步 **ΔL 39.5 / ΔE2000 42.07**，不是一档，是一块亮板。

### 4. 可辨阈值（引用，不重测）

- ≥3 art px 色带：`ΔL* ≥ 5` 看得出，`ΔL* ≥ 6` 稳定；`ΔL* < 4` 不可用（`ΔE2000 < 3.1`）。
- 出处：`docs/evidence/palette-threshold/`（可复跑；「ΔL 6 稳定」即该表结论）。旧文里的 ΔE 2.96/3.50/4.08/4.88/5.53 与 12.85 为简化式误值，已更正。

### 5. 审计不覆盖设定集

- `audit-palette --strict` 只看默认世界与 prefab，不看各 pack 的 24 个值；ADR 自己也写明这点。
- 所以「扩预算后 `--strict` 仍绿」**不能证明**设定集侧没超预算；扩预算时要么同步扩展审计范围，要么明确接受这条盲区。

## 影响面（以「扩到 26」计）

| 面 | 要改什么 | 代价 / 风险 |
|---|---|---|
| 审计 | `BUDGET.world` 24→26、`PROPOSED_WORLD` 加 2 项 | 两处常量 + 一份 26 色表 |
| 测试 | `WORLD_BUDGET` 24→26、`UNION_BUDGET` 32→34、`PROPOSED_WORLD` 加 2 项；「并集 32」断言改 34 | 11 条相关断言同步；漏一条就红 |
| 运行时闭集 | `settings/load.ts` 的 24 槽判等 → 26 槽 | 所有 pack **必须**补同样槽位；`loadSettingPack` 对 24 槽各不同值做校验，少一个就装载失败 |
| 设定集 | 至少灯潮界等现有 pack 补 2 个值；未补的 pack 全部装载失败 | pack 数量 × 2 个值；还得给新槽起名、定语义 |
| 文档 | `ADR_PALETTE_24.md` 决策 2 明写「加第 25 个色 = 再走一次 ADR」；`SPEC_V2.md` §4.2「24 色不变」要改 | 引擎级约束被改写；未来「再加一个」的阻力降低（预算蠕变） |
| 失去 | 「一屏最多 24 源色」的可证性；两层并集 32 的硬数字 | 这是 ADR 补记里唯一可验的量化约束 |

## 选项与代价（不排序、不推荐）

### O1 不扩预算：暖泥岸不做

- 做法：白天岸线只保留现有暖色两档（`plaster` / `trim` 当沙，外加一条冷灰或砖红），或干脆不做三段。
- 改动面：零预算改动；只改 `pack.ts` 的岸线配置。
- 会得到：预算不变量不变、pack 不用补槽、审计继续有效。
- 会失去：白天暖泥岸「湿 → 干 → 沙」的读法；两档 ΔL 5.7 只在 ≥5px 时刚过线，做不出「湿泥变干」的过渡。
- 怎么验证：4× 截图对照参考页 67；按阈值表量相邻 ΔL，若 < 5 直接判「读不出」；不宣称「暖泥岸已完成」。

### O2 扩到 26

- 做法：新增两档暖中性（目标 L\*≈45 / 58、h 60–90°、C 10–20），26 槽闭集。
- 改动面：上表全部；另加所有 pack 的 2 个值。
- 会得到：白天暖泥三档可落地；阈值上第一段 ΔL≈13、第二段≈13（按目标值），两段都远超「稳定」。
- 会失去：24 不变量；并集 32 的硬数字；每加一个 pack 都要维护 26 槽。
- 怎么验证：`audit-palette --strict` 26/26 over 0；`palette-budget` 11 条；全部 pack `loadSettingPack` 装载；4× 截图按阈值表量三档 ΔL；若扩审计范围，还要 `--strict` 覆盖 packs。
- 前置判断（owner 要回答）：24 这个数是否仍然要作为引擎级不变量？如果答案是否定的，这条才有讨论空间。

### O3 不扩预算，改用构件表达岸（跨选项）

- 做法：岸由石块、草簇、湿痕小块读出来，不靠色阶；颜色只用现有 token（详见 `P1_SHORE_BAND_DESIGN.md` v3 构件化设计 / `P1_SHORE_ROOTCAUSE.md` §4）。
- 改动面：生成器 + 类型 + pack 数据 + 测试；**零调色板改动**。
- 会得到：预算与 pack 闭集完全不动。
- 会失去：色阶层面的「湿→干」连续感；靠结构读出岸，需要接受确定性散落的美术方向。
- 怎么验证：确定性单测、零入水、每格 1–3 件；4× 截图目视；边界破碎度（最长连续直边 ≤ 8 art px）。
