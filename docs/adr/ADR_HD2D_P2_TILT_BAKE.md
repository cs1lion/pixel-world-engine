## 背景

第一版按「只糊地形」实现：糊图放在 depth −5（后来试过 2.9 以免盖掉码头轨道）。
演示图被用户判**未成型**，理由是「糊带内木栈梯、栏杆、船、栈台全是锐边」——
同一区域水面软、结构硬，眼睛读成两张图叠在一起，而不是景深。

排查结论（2026-11-08 实测，`dengchao` 渡口，视口 480×320 @2×）：

- **静态入口一个都没漏调用。** 用户点的三处摆件都是 depth ≤ 6 的 Graphics：
  木栈是 `harbor-view` 的 `fillRect(176, py+3, 32, 12)`（depth 4）、栏杆是
  `setting-scenery` 街面层的 `fillRect(_, 132, _, 2)`（depth 1）、船壳在同一个
  `fixtures` 里。命令缓冲取证确认它们都带 `dofStatic` 标记，运行期 `sources = 9`。
- 真正的原因有两条：
  1. **核太小。** 第一版 `blurRadius = 1`（k=3）。整数 box 的台阶梯度上限是 `C/k`：
     180 反差的木栈边只能压到 **61**，读数上仍是锐边；
  2. **≥1000 的建筑/道具不在闭包里，也进不来。** 它们的 depth 与人物逐行交错
     （`sceneryDepth` 与 `villagerDepthAt` 都按落地行），一张平面糊图不可能同时
     压在建筑上、垫在人物下；Phaser 4 的 WebGL 后端又不支持 GeometryMask
     （只打警告）。这是 S-4 未闭合项，不是 compose 漏调用。

## 决策

1. **闭包只按标记收集**：`markDofStatic` 打标的 Graphics / Image 才进合成，
   按 `depth` 再按显示列表顺序排序；不按 depth 猜测。新增贴地入口不标就不进闭包
   （少一层会被 C7 的点名窗口抓到）。
2. **糊图 depth = 999**：压在整条贴地带（闭包最高 6）之上、人物与立体构件的
   `ALTITUDE = 1000` 之下。原件不隐藏、不做 mask，被糊图整片盖掉。
3. **核的实现不动，窗口半径可以越过 §13.3.2 的档位表，但必须给出同一组边缘的
   实测读数并记账。** 本版 `blurRadius = 5`（k=11）：木栈 180→17、栏杆 73→7、
   船壳 176→11，都过判据的 <20；而 B3 的上限 k=7 在同一组边上停在 26/21/25，
   **过不了 <20**。代价是远带去重色数 239→4,630（§13.3.2 的 24 色告警在此成立）。
   档位上限与「糊带内 <20」这两条在 180 反差的边上数学互斥，裁决权交回给人；
   要退回 B3 只改一个常数，C7 会如实变红。
4. **判据落成可跑的数，不靠人再看一眼**：`test:dof` 在糊带内按**世界像素点名**
   三处已知摆件边缘（木栈竖边 / 栏杆横边 / 船壳），要求 `?dof=off` 下 >40、
   on 下 <20，且 on 的 ≥40 硬边像素为 0。整条远带的最大梯度只记账、不设闸——
   里面还有 ≥1000 的建筑顶和画在糊图之上的地点标签，它们本来就不该糊。
5. **读数口径与门禁同源**：两页的世界时钟先对齐到整分钟再冻，否则按世界时刻重画的
   渡口灯影与船档期会让 `totalCommands` 凭空差 8 条，C4 会把「世界差了几拍」
   误报成「这一笔多画了东西」。

## 理由

- 「哪些入口没被 compose 调用到」是一个可以被命令缓冲直接回答的问题，不该靠观察截图
  猜层号；本 ADR 的证据链是「命令缓冲 → 标记集合 → 逐字节差异 → 法线梯度」四段，
  每一段都能单独复跑。
- 核尺寸是**观感参数**，不是实现；把「观感不够」误诊成「入口漏了」会让人去改收集逻辑，
  越改越远。反过来，把尺寸悄悄加大而不记账，会让 24 色纪律的告警失效。
- 糊图压在最上层是对「一张平面图」这个前提最诚实的用法：它的能力边界就是
  「贴地带整片」。要求它同时服务建筑与人物，等于要求它有逐行结构。

## 后果

- `?dof=off`（默认）不创建任何对象、不申请纹理、不改任何绘制项；
  `images 38→39`、`drawCalls 170→171`、`totalCommands 25,983→25,983`（对齐时钟后逐字节相同）。
- 失败方向被写死：闭包少一层 → C7 点名窗口变红；核退太小 → C7 变红；
  把整条远带当判据 → 会被标签与建筑顶误伤，所以 `band` 只记账。
- **S-4 仍然未闭合**：≥1000 的构件跨越焦线时会在远带里露出锐边
  （本机位实测：一栋楼的屋顶顶边进入远带约 9 world px）。要做全需要逐行重排的
  立体闭包，不在本 ADR 范围；这条不解决，P2 不能称为「完全成型」，只能称为
  「贴地带成型、立体构件留给 S-4」。
- 收工口径：本分支只留实现 + 测试 + docs 三笔；若后续判定关路径，按 S-9 把
  烘焙 + 整数 box blur + 双缓冲留在实验分支归档，主线上不留半开开关。

## 备选

| 方案 | 为什么没选 |
| --- | --- |
| 继续只糊地形（depth −5） | 就是被判未成型的那一版：水面软、摆件硬 |
| 用 mask 让原件在糊带让位 | Phaser 4 WebGL 的 GeometryMask 只打警告，不生效 |
| 把 ≥1000 的建筑也烘进闭包 | 与人物逐行交错，同一张平面图压上就盖住人物，垫下就压不住建筑 |
| 保持 B1/B3 不动、改判据到 <40 | 判据是用户给的裁决口径；改判据等于自己改卷子 |
| 只加层数不管核尺寸 | 实测 k=3 时同组边停在 61/25/56，读数仍是锐的 |
