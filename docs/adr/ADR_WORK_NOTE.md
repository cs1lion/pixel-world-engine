# ADR_WORK_NOTE：作业牌子上的一句话由模型写，事实由世界给

- status: aligned
- verified_at: 2026-11-10
- verified_by: agent（用户「先把最基础最需要的真实作业和生活跑起来」的延续：第 1 步让 LLM 参与作业语义）
- evidence: `server/oracle/work_note.py`, `server/tests/test_work_note.py`, `world-client/src/world/work-note-client.ts`, `world-client/src/world/simulation.ts`, `world-client/test/work-note.test.ts`

## 1. 问题

场所产出账（`ADR_SITE_OUTPUT`）让「搬炭」真的搬出炭，但**牌子上还是三个字**：
炉匠一年到头写「搬炭」，洗衣妇一年到头写「收衣裳」。场所身份、在场的人、
库存到了多少，全都没有进入这一行字——作业有了产出，仍没有「意思」。

用户认可的最小切口是：**作业不写死在设定集里，由模型按现场说一句**。

## 2. 决策

- **模型的权限只有措辞，没有事实。** 请求里把场所、活动、存货、第几天、
  在场的人、**牌子原文案**（`canonical`）一起递过去；提示词明写
  「只能用这些事实，不许编」，「换一种说法，事实一个都不许变」。
  牌子是对外唯一凭据，编出来的细节会被当真。
- **单开一个端点 `/api/world/work-note`，不塞进 `/api/world/intent`。**
  那条路的输出是白名单命令（会改世界），这条路只写一句话（进 `routineLabel`，
  随后入档）。失败面完全不同：意图解析失败要回 unknown 让人知道没听懂；
  牌子失败只该退回原文案，不该让世界停摆、也不该在页面上留红字。
- **失败一律 `{"ok": false}` + HTTP 200，客户端回 `null`，不抛不重试。**
  没有 Key 是常态（离线开发、CI）；超时 12s（意图那条给 40s，因为玩家在等，
  牌子是背景装饰，慢请求不许压着后面的拍）。
- **落回世界要过两道门**：她此刻仍站在这处（`routineIndex - 1` 算出的
  `siteId` 与请求一致）、牌子上不是空话。异步回来时她可能已经走开，
  把话挂到一个不在那儿的人身上就是让牌子说谎。
- **谁干活由世界里那个 `villagerId` 给，不靠坐标猜。** 最初版本在场景里按
  位置反查「谁站在这儿」，同一格站着两个人就会挂错；请求里本来就知道是谁。
- **牌子失败不影响世界**：产出账照记，牌子留原文案。这条由测试钉住。

## 3. 不在范围

- 不做对话、不做多轮、不让模型决定去哪做工：那会越过「世界自己跑，LLM 只发
  白名单命令」的总边界。
- 不做离线回放的重放模型调用：牌子的结果进存档（`routineLabel` 本来就入档），
  回放读档即为原文，不重调模型。
- 不改 `ActivityId` 闭集、不改产出速率与消耗。

## 4. 代价与已知边界

- **多了一扇网络门。** `test/purity.test.ts` 的封闭清单从三扇变四扇，理由写在
  清单注释里：同一类路，不同门（一扇的返回会变成命令，一扇只变成一行字）。
- **牌子文案不回灌世界语义。** 模型说「弯腰把炭码齐」不会改变产出账，也不会
  被别的村民读到。要让它有后果，得等「产出物有名字与来历」那一步。
- **无模型时牌子仍是原文案。** 这是有意的退路，不是缺陷；测试里把它当正常路径。

## 5. 验证

- 服务端 `test_work_note.py` 4/4：无模型回 200 + `ok:false`、提示词只带给定事实、
  `clean_note` 去引号截断、模型抛错仍回 200。
- 前端 `test/work-note.test.ts` 5/5：请求事实齐全且 `canonical` 与场所标签同句、
  取走即清空、场所对不上/人不在都不写、空话被拒收、断网/超时/500/`ok:false`/
  坏 JSON 一律 `null`、牌子失败后产出账照记。
- 全量 2665 通过 0 失败；十一道闸门 11/11；服务端 570 通过 1 跳过。
