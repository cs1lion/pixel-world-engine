## 1. 问题陈述

v1 把引擎骨架说清楚了：世界自己跑、命令过白名单、记忆是时间线。写完之后的这轮
查缺补漏发现三处它没有覆盖、或者自相矛盾的地方。

**一、视觉与设定集只到「换皮」这个词，没有验收面。**
v1 全文没有一处提到构图、色板预算、区域配色、UI 语言、折返结构——而设定集手册
十二条自检里有七条是可判定的（剪影可分、每区三色、紧张段后有呼吸屏、终点回到起点）。
这些不是美术的事后装饰，是引擎必须提供的能力：没有区域色板槽位，第二份设定集
就长不出自己的颜色；没有「同一场景重新演绎」的状态位，折返就只能是文案。

**二、设定集的五条世界规则，引擎只接得住两条。**
手册的世界观是「灯潮界」：灯油既是货币也是寿命、潮汐就是时钟、名牌可抵押、
渡有仪式、清洗即还原。v1 里只有前两条有落点（灯油、潮汐）。剩下三条不是没做，
是**世界状态里没有地方放它们**：抵押需要一个「名字失效」的角色状态，仪式需要
一个跨区通行的门槛判定，清洗需要一个「污浊度」的物件属性。

**三、三处内部冲突，票里已经埋着。**

| 冲突 | 位置 | 后果 |
|---|---|---|
| `tide.setLevel` 直接设潮位 vs 潮位是 `now` 的纯函数 | SPEC §4.3 vs §4.4 | 命令一落地，「同一存档回放出同一条曲线」当场破功 |
| 命令表有 `weather.set('storm')` vs 类型只有 `'clear' \| 'rain'` | SPEC §4.3 vs `types.ts` | 白名单收下一条渲染层不认识的值 |
| SPEC §4.1 布局有 `server/` 与 `memory/` vs 仓库里两者都不存在 | SPEC vs 仓库 | #5 #6 #7 三张票的验收条件里写着 pytest，但仓库没有 Python 工程 |

## 2. 解决方案

v2 不推翻 v1 的引擎决策，补四件事：

1. **给视觉一层引擎级的验收面**：区域色板槽位、24 色预算在设定集里的映射规则、
   折返状态位、呼吸段（留白）机制。设定集可以换，这四样是引擎提供的槽。
2. **把设定集的五条世界规则拆成「引擎能表达的」与「第二份设定集的」**：
   本版只加引擎缺的那三个状态位（名字状态、通行门槛、污浊度），不实现灯潮界的剧情。
3. **消掉三处冲突**：潮位改成「有期限的覆盖」、天气补 `storm`、明确 `server/` 是 v2
   的交付物而不是既有资产。
4. **重切票据**：v1 的 #4–#9 有两条阻塞边是错的（见 §7），v2 按新的 frontier 重排。

## 3. 用户故事

### 世界自己跑

1. 作为使用者，我打开页面就能看见一座在动的镇子，不必先下达任何指令。
2. 作为使用者，我能看出潮水在涨在退，而且低处真的会被淹。
3. 作为使用者，我能感觉到居民按自己的作息活动，不是围着我转。
4. 作为使用者，我离开一段时间再回来，镇子还是那个镇子，只是过了几天。
5. 作为使用者，我在涨潮时看见铺子关门、人往高处走，而不是照常营业。
6. 作为使用者，我能看见天气从晴转雨再转暴，转的过程是渐变的，不是开关。

## 4. 实现决策

### 4.1 两份设定集，不是一次替换（用户 2026-10-25 确认）

现有的四个分区（industry / scholarly / agriculture / living）**保留为设定集 A**，
继续承载现有 646 个测试与全部验收数字。灯潮界的六个区域做成**设定集 B**，
作为 #9「换配置能长出另一座镇子」的真实对照物。

理由：直接替换会让 #9 的验证失去对照物，而且现有测试里凡断言分区名的都要改；
保留两份则 #9 从「纸面承诺」变成「两条启动路径」。

设定集 B 的六个区域与它们的色板槽位（映射到现有 24 色，见 4.2）：

| 区域 | 功能 | 主色 | 点缀 | 禁用 | 瓦片母题 |
|---|---|---|---|---|---|
| 渡口站台 | 新手、规则引入 | `deepShade` | `amber` | `terracotta` | 石像、候车亭、断续路灯、潮痕墙 |
| 灯街 | 社交、商店 | `timber` | `warmLight` | `water` | 摊位、幌布、成串纸灯、油锅蒸汽 |
| 叠浪楼 | 主线、工作 | `terracotta` | `trim` | `grassLit` | 多层木构、朱红桥、格窗、悬挑回廊 |
| 炉底层 | 劳作、密道 | `charcoal` | `ember` | `pale` | 抽屉墙、管道、煤堆、蒸汽阀 |
| 浅滩轨道 | 呼吸段 | `copper` | `plaster` | `terracotta` | 水面轨道、孤站牌、倒影 |
| 积尘滩 | 清污、暗面 | `soil` | `moss` | `amber` | 废弃物堆、锈蚀机械、淤泥 |

### 4.2 色板：24 色不变，设定集只做映射（用户 2026-10-25 确认）

设定集手册的 11 色基础板与仓库里冻结的 24 色是两套值，**不合并、不新增**。
设定集 B 的色板通过一张映射表落在现有 token 上：

| 手册色 | 色值 | 落到的 token | 说明 |
|---|---|---|---|
| 夜青 | `#1B2A41` | `deepShade` / `cloakDark` | 夜空用 `deepShade`，冷影用 `cloakDark` |
| 潮灰蓝 | `#3D5A73` | `water` | 水面与冷区地面 |
| 浅滩青 | `#8FC1B5` | `copper` | 浅滩轨道；现有唯一偏青的中间调 |
| 米白 | `#F2E8CF` | `pale` / `plaster` | 纸张用 `pale`，灰泥墙用 `plaster` |
| 朱红 | `#C8372D` | `terracotta` | 桥、栏杆、印章 |
| 金 | `#E0A526` | `amber` | 贵重物、权威者 |
| 灯橙 | `#F28C28` | `warmLight` / `ember` | 发光最亮一档用 `warmLight`，炉火用 `ember` |
| 煤黑 | `#1E1A1D` | `ink` | 炉底层、轮廓线 |
| 灰褐 | `#6B5E55` | `charcoal` | 积尘滩、废弃物 |
| 病黄绿 | `#A3A847` | `moss` | 污浊；偏绿，是这套映射里最勉强的一个 |
| 藤紫 | `#6A4C93` | 无 | **缺**。神秘事件暂用 `cloak` 顶上，缺口记在 §8 |

结论：11 色里 10 色有落点，`藤紫` 缺。**不为此加第 25 色**——等真正要画神灵时
再走 ADR，而不是现在为了对齐手册破预算。

### 4.3 潮位：有期限的覆盖（用户 2026-10-25 确认）

`tide.setLevel` 不再直接写潮位，而是写一条**覆盖**：

```ts
// 来自设计决策，不是现有代码
interface TideOverride {
  readonly level: number;      // 0..1，命令给的潮位
  readonly until: number;      // 世界时间，到期自动失效
}
// 有效潮位 = override 存在且 now < until ? override.level : tideLevelAt(now)
```

- 覆盖存在世界状态里，**进存档**，所以回放仍然确定：给定存档 + 步长，曲线唯一。
- 到期自动失效，世界回到 `tideLevelAt(now)` 的节律上——「潮汐是时钟」这条不被夺权。
- **过期不删字段，读的时候判**（`now >= until`）。要"清理"的状态迟早会在某条
  路径上漏掉清理，而漏掉的那一刻回放与读档就分叉了。
- 时长超上限**拒**、不夹到上限：夹住会让「拨 10 分钟」变成「拨了 2 分钟」而回执
  说成功——世界做了件别的事，调用方还以为办成了。拒绝码在 `tideOverrideRejection`。
- 时长由命令给，有上限（默认 2 分钟，不超过一个周期）。上限是 L1 硬规则。
- `tideLevelAt` 保持纯函数、不读墙钟。这条测试（`purity.test.ts` 的「潮汐逻辑不读墙钟」）
  继续成立，不需要改。

### 4.4 天气补 `storm`

`Weather` 从 `'clear' | 'rain'` 扩成 `'clear' | 'rain' | 'storm'`。

- `storm` 是 `rain` 的强度档，不是新机制：`WeatherState.intensity` 已经能表达浓淡，
  渲染层（`render/weather.ts`）按 intensity 插值，不需要新分支。
- 白名单里 `weather.set` 的取值域同步扩到三档。
- 旧存档只有两档，读档时 `storm` 缺省不存在，不需要迁移。

### 4.5 折返状态位

`world_change_version` 从 v1 的「存档字段」升级成**世界状态里的一个计数**：

- 每次世界被玩家实质改变（落楼、拆楼、神迹、潮位覆盖）加一。
- 渲染层与设定集读它，决定「同一个场景现在该长什么样」：
  设定集 B 的渡口站台按它分三态（初入 / 立足 / 折返）。
- 它进存档，且**不参与**确定性回放的判据——它只影响画什么，不影响世界怎么走。

### 4.6 引擎新增的三个状态位（承接设定集的后三条规则）

只加状态与判定，不加剧情：

| 规则 | 引擎提供 | 不加什么 |
|---|---|---|
| 名牌可抵押 | 角色多一个 `nameState: 'held' \| 'pawned'`，抵押后不再被派活、不再出现在关系记忆的写入源里 | 不做抵押 UI、不做经济数值 |
| 渡有仪式 | 跨区通行多一道 `gate` 判定：区域可以声明 `requires: 'lamp' \| 'shoes' \| null`，不满足则寻路绕开 | 不做仪式动画、不做失败惩罚 |
| 清洗即还原 | 物件多一个 `grime: 0..1`，渲染层按它叠噪点；洗到 0 时露出一条 `reveal` 文案 | 不做清洗小游戏、不做物品栏 |

三者都进 `Simulation`，因为它们改变世界行为（派活、寻路），不只是画法。
这与灯油相反——灯油只进渲染层，那条边界不动。

### 4.7 呼吸段（留白）

设定集手册的第 7 条（紧张段之后必须有一屏呼吸）落成一条**世界侧规则**：

- 每个区域的配置可以声明 `breathing: true`。设定集 B 里是浅滩轨道。
- 呼吸区里不派活、不触发随机事件、不弹提示；氛围实体（萤火、猫）照常。
- 这是「世界不围着你转」的延伸：**留白也是规则，不是没内容**。

### 4.8 UI 语言：纸签、木牌、印章

- 全部是 DOM overlay。中文与长文一律不进 canvas（既有 `no-cjk-canvas.test.ts` 守着）。
- 边框保留手工的不规则感，重要信息用朱红印章（`terracotta`）强调。
- 数字用较粗的像素体；物品图标 16×16，技能图标 24×24。
- 神谕抽屉是纸签条，输入框像在纸上写字；选项是木牌。

### 4.9 分辨率与栅格

沿用现有：480×320 逻辑分辨率、16px 瓦片、固定 2× 整数缩放。
设定集手册建议的「地形 16×16、建筑以 16 为模数」与此一致，不需要改。

### 4.10 `server/` 是 v2 的交付物

v1 的布局把 `server/` 与 `memory/` 写成既有目录，实际都不存在。
v2 明确：`server/`（FastAPI + pytest）与 `memory/` 由 #5 #6 #7 从零建立，
CI 增加一个 Python job。在那之前，世界侧必须能在没有服务端的情况下完整运行——
这条已经是现状，v2 把它写成验收条件而不是巧合。

## 5. 测试决策

**好测试的标准**：断言外部可观察行为。世界侧的单测守「`world/` 不 import Phaser」；
渲染侧的断言落在纯函数（配方、色板映射）而不是画面像素。

**接缝**（按优先级，越靠前越优先复用）：

1. **`Simulation` 的命令入口**——所有改变世界的路径都从这里过（含潮位覆盖、天气、
   建造、拆除、仪式门槛）。一条接缝覆盖绝大部分验收，不新开。
2. **快照 → 渲染的纯函数**——`day-phase.ts` 的配方、`palette-data.ts` 的映射、
   设定集的区域色板，都是纯函数，喂数据断言输出。
3. **源码扫描契约**——沿用 `purity.test.ts` 与 `no-cjk-canvas.test.ts` 的形态：
   潮汐不读墙钟、灯油不出现在 `Simulation` 的读路径、24 色预算。
4. **事件日志客户端**——注入 fetch，覆盖超时与坏数据（新接缝，只有一个）。
5. **配置包 → `buildWorld`**——第二份设定集启动，断言世界结构与色板映射。

不新开「渲染截图对比」接缝：像素级回归成本高、脆，且色板预算已经有审计脚本。

**先例**：

- 潮汐可复现：`test/tide.test.ts` 的「回放可复现：同一串步长得到同一条潮位曲线」。
- 涉水绕路：`test/tide-path.test.ts` 的「涨潮时绕上石板大路」。
- 源码扫描：`test/purity.test.ts`、`test/no-cjk-canvas.test.ts`。
- 色板预算：`scripts/audit-palette.mjs --strict`（已在 CI）。

## 6. 不在范围

- 语音、对话、立绘（旧仓的事）。
- 多角色协同：v1 是 1 主角 + 若干 NPC，v2 不变。
- 记忆检索（向量库）：MD 到几百条再谈。
- 结构层自进化（LLM 生成新 Schema）。
- 波浪与涟漪动画。
- 旧仓的督办台账、durable、Worker。
- 灯潮界的**剧情**：三幕、双面表、角色阵容都是设定集内容，不是引擎交付物。
  v2 只交付承载它们的槽位。
- 抵押 / 仪式 / 清洗的**玩法循环**：v2 只交付状态位与判定，不做经济、不做小游戏。
- 声音与配乐。
