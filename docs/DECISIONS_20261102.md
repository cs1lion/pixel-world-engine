# 2026-11-02 代理代行决策记录

用户授权代理在 8 小时内按既定路线连续执行，并允许代为做决定。本文件只记**需要产品判断、
但用户已提前给出原则（可回退 + 精品化 + 不造假）**的岔路，以及选择与理由，供用户醒来复核。
纯机械的改动（注释纠错、坐标随内容移动）不在此列。

## T2 真实时钟

### D1. 真实时钟是显式开关，默认仍走加速模式（**已被 D11 取代**）

- 选择：`?clock=real` 才切 1:1；默认仍 `timeScale=6`。
- 理由：改变默认会同时改变演示观感、截图基线与所有浏览器回归的节奏，属于不必要的连带
  风险。真实时钟要能被验收，不要求它成为默认。
- 可回退：删掉 URL 参数那一支即可，默认路径一行未动。

### D2. 锚点只用于新世界，读档不改写世界时钟

- 选择：新世界把 `now` 锚在「本地今天已过了多久」；读档沿用存档里的 `world.now`。
- 理由：存档里的 `now` 是世界自己的事实（ADR_SAVE §1）。为了对齐日界去改写它，会让
  记忆与编年史的时间线出现回跳；那比「老档的日界不落在午夜」更难解释。
- 代价：老档在真实时钟下仍按它自己的日界关账，直到玩家开新档。已在代码注释写明。

### D3. 离线超过 7 天：合并不是重放

- 选择：跨 1–7 天逐日关账；超过 7 天只关一次，记 `skippedDays`。
- 理由：把 10 天的逐拍行为压进一帧补跑，补出来的不是「中间发生了什么」，是假的。
  关账仍走 `world.dayClosed` → `onVitals` → `stepCreatorDayClosed` 这条既有路径。
- 代价：中间那些天在编年史上表现为「一段时间过去了」，不是十份完整日报。

### D4. 墙钟回拨暂停后不自动恢复

- 选择：回拨超过 5 分钟即暂停推进，状态行明说；提供 `resume()`，但没有自动恢复。
- 理由：静默把 `now` 改回去会让世界进入一个无法回放的时刻；暂停是可解释的，
  自动改写不是。自动恢复需要一个人来判断「现在几点了」，本阶段不替人判断。

## T3 感知与记忆内核

### D5. `indoor` 按「事在哪发生」判，不按 placeId 猜

- 选择：`task_done` 在屋里（室内），`building.built/removed` 在门口（室外），
  神迹/天气在落点（室外）。
- 理由：`building.built` 的 placeId 是那栋楼，但事情发生在门口；按 placeId
  一律判室内会让「新楼立起来」没有目击者。
- 可回退：`RuntimeObservation.indoor` 是可选字段，删掉就回到「一律室外」。

### D6. 听见第一版：墙是硬阻挡，半径按声音类型

- 选择：`speech 6 / work 8 / impact 12 / miracle 20`；`hasLineOfSight` 不通就听不见；
  室内声音只传同房间。
- 理由：先把三条通道（距离、墙、类型）真实接上，阈值是数字不是规则，后续可调。
- 代价：隔墙的声音完全听不见，比真实世界更硬；这是第一阶段刻意选的可解释版本。

### D7. 印象只由「目击别人交活」生产

- 选择：`task_done` 的目击者（非当事人）写一条关于当事人的 `impression`；
  方向性是「看见的人 → 被看见的人」。
- 理由：这是当前数据里唯一稳定的「一个人看见另一个人做事」的形状；
  互助/冲突的数据形状还没有，不先编一个。
- 代价：印象来源单一；等事件协议补上更多双向形状再扩。

### D8. 记错只发生在「听来的」记忆，断言层不改

- 选择：`heard` 条目按 `eventRef + holderId` 确定性选约 1/7 加一种偏差；
  `retell` 的「只丢细节、放大情绪、方向不变」一个字没动。
- 理由：协议对**断言**的保真约束仍然成立；个人记忆可以错，但 `eventRefs`
  仍指向真实事件，查得回原文。
- 代价：只有听见的记忆会错，目击记忆永远准确；第一阶段先划清这条边。

### D9. 时间线不迁移老档

- 选择：`timelineFor` 直接从既有 `eventRefs` 聚合；新增的 `bias` 是可选字段。
- 理由：`eventRefs` 在类型上就是非空数组，老条目天然带事件 id；为不存在的
  缺失情况写迁移，是给假问题写代码。
- 代价：如果历史记忆 JSON 本身损坏（缺 `eventRefs`），整段记忆会被 `fromJSON`
  拒绝——这是既有行为，没有因为本阶段变宽或变严。

## T2 补：跨会话基线

### D10. 时钟基线放独立 localStorage 键，不进存档

- 选择：`xiaoxi.pixel-world.real-clock.v1:<worldId>` 存 `{ lastWallMs, lastWorldNow }`；
  不扩 `world.` 契约。
- 理由：锚点是「这台设备上次何时开过页面」的运行环境信息，不是世界的自有事实；
  放进存档会让同一份档在换设备/换时区后带上别人的时钟。
- 老档（v1/v4）没有这个键：第一次进入按「从现在起计时」，不凭空补历史。
- 目标世界时间 = 基线世界时间 + 墙钟经过时间；只向前推，不倒退。回拨超过
  5 分钟沿用既有暂停策略，且暂停期间不更新基线。

### D11. 真实时钟改为默认（**已被 D13 取代**）

- 选择：不写参数就是真实时钟 1:1，日界本地 00:00；加速必须显式
  `?clock=fast`（或 `accelerated`），或只给合法的 `?speed=`（历史入口，
  截图与回归一直这么用）。`?clock=real` 压过 `?speed=`。
- 理由：产品承诺「24 小时制和真实世界时钟同步」。把同步做成需要额外参数的
  开关，等于承诺只在演示入口成立。加速模式保留给演示、截图与需要压缩时间的
  回归，但不再冒充默认。
- 代价：页面长时间开着时世界按真实速度走，看不快；需要快节奏时必须显式
  `?clock=fast`。截图与浏览器回归继续用 `?speed=1`，它们要的是可复现，
  不是绕过默认。**（此代价后来成为 D13 回退的触发点之一。）**

### D12. 老档日界对齐：只提示、点了才改；改锚点，不重编 day（**只适用于 `?clock=real`**）

- 选择：读档时若世界日界与本地 00:00 的偏移超过 5 分钟，提示一次。玩家点
  「对齐」才把世界时钟**向前跳** `deltaMs`（正好等于日界的本地位相），使下一个
  世界日界落在本地 00:00。历史记忆与事件的 `day` / `when` **一个字段都不改**。
- 算术更正：老档实测日界在本地 07:01，前跳约 **7 小时 1 分**；当前世界日因此
  缩短为 **16 小时 59 分**（不是被拉长 16 小时 59 分）。提示与状态行同时写这两个数。
- 副作用：跳过的这段世界时间不逐拍回放；村民 `nextRoutineAt`、工位
  `startedAt` / `until` / `since` 随跳变**统一平移同一量**，所以剩余时长不变；
  历史时间戳（`completedAt`、外环 `lastClimbAttemptAt`）不动——它们不是未来定时器。
- 撤销：`deltaMs` 与 `fromNow` / `toNow` 存独立键
  `xiaoxi.pixel-world.clock-align.v1:<worldId>`，不进 `world.` 契约；撤销把同一
  `deltaMs` 移回，`now` 与相对定时器回到原值。
- 「暂不」按日界相位持久化：重启后同一相位不再弹；维护条（`?debug=1`）的
  「检查日界对齐」绕过暂不重新提示，「撤销对齐」只在对齐记录存在时出现。
- 边界：若跳变本身跨过世界日界，仍走既有 `dayClosed → onVitals →
  stepCreatorDayClosed` 关账；撤销只还原 `now` 与相对定时器，**不反结算**已经
  关掉的那一天（记录里的 `dayBefore` 可查）。老档样本不跨日界。

### D13. 默认回到游玩时长驱动；真实时钟降级为显式开关（取代 D11）

- 选择：不写参数就是**游玩时间驱动**——`timeScale = 6`，页面开着才走，
  **关页面即冻结**，重开从存档断点（`world.now`）继续。默认路径**永不补算**
  任何离线时间。真实时钟必须显式 `?clock=real`；只有它保留逐日/合并补算、
  跨会话基线与老档日界对齐。`?clock=fast` / `?speed=` 仍是倍率入口。
- 理由：**页面没运行时世界不能积累信息。** 离线期间没有一帧仿真、没有任何
  事件发生；按墙钟补算只能把日历翻过去，那几天在世界里是空的，补出来的「历史」
  等于伪造。D11 把这种补算设成默认，等于默认路径就在编故事。
- 保留而不是删除：`RealClock`、离线补算与 D12 的日界对齐仍服务于显式选择
  `?clock=real` 的玩家（他要的是世界与墙钟连续），代码不删；但文档与 UI
  必须写明这些机制**只属于 real 模式**。
- 模式门槛：默认模式下 `initClockAlignment` 不读对齐记录、不检测、不提示；
  `?debug=1` 维护条的「检查日界对齐」置灰，读数写明「只在真实时钟模式
  （`?clock=real`）下可用」。`clockAlignmentView()` 直接返回 `available: false`，
  不会为了显示而算一次检测。
- 断点语义：`pagehide` 时 `world.now` 随存档落盘；重开 `Simulation.fromSave`
  原样读回，不因墙钟推移推进世界。`test/playtime-clock.test.ts` 钉住「同一份档
  隔 0 天与隔 3 天读回，`now`、事件与记忆完全一致」。
- 代价：世界不再与现实日历同步；离线期间世界停在原地。这是刻意的取舍——
  宁可没有那几天，也不要一段没有事件发生过、却出现在编年史上的日子。
