## 一、为什么改口径

### 1. `phases`：量到了渐变中间帧

`FADE_MS = 900`，按累计 delta 推进；`?time=noon` 只是把目标定在 noon，页面加载后仍要
走完 900ms 渐变。冷启动时墙钟 2200ms 里游戏时间推进不足 900ms，截图拍在过渡中：
noon 被拍成比 dawn 还亮的 66.10（正常稳态是 58.9），差 -0.68 被判红。
这不是渲染坏了，是**采样点没落在稳态**。

改法：每个刻度的页面等 `window.Oracle.ecoState().advanceCount` 再推进 60 帧（≈1s）才截图；
外加一整轮不计分的预热跑（四刻页 + 夜雨页，读数丢弃）。

### 2. `render-budget`：量的是「逻辑步进节奏」，不是「上屏帧」

旧判据比的是 `advanceCount`（世界步进次数）中位：恢复 41 vs 前台 57 就是 0.72，
判红。但同一段里 rAF 稳定在 59.9——**上屏一点没掉，掉的是场景自己跳帧的节奏**。
隐藏期间 rAF 被掐掉，回前台后合成器、Phaser 步进都要重新起转，整段中位天然带爬升尾巴。

改法：

- 末秒判据：恢复段**最后 1 秒**的 rAF 间隔中位 ≤ 前台间隔中位 ÷ 0.9
  （等效「末秒帧率 ≥ 前台 × 0.9」，阈值 0.9 不变）。
  注意方向：间隔越小越快，写成 `间隔 ≥ 前台 × 0.9` 会变成「恢复不许比前台快」，与原意相反。
- 逐秒硬底线：恢复段**任何一个 1 秒窗口**的帧率 ≥ 前台 × 0.5（新增，只更严）。
  专防「先崩到 15 帧、末秒爬回 59.9」被尾巴判过。
- 读数全打出来：恢复整段中位、末秒中位、4 个逐秒窗口帧率、前台帧率、推进口径。

### 3. `daily-prop-cost`：墙钟量的是「机器有多忙」

单次墙钟在 `node --test` 并行跑时夹着排队时间：同文件相邻用例全过，只有这条红，
实测 54.62ms / 100.28ms，而文件头常态 0.3–5ms。主指标改为 `process.cpuUsage()`
前后差（user + system），预算仍 50ms；墙钟降为 diagnostic 附注。

Windows 上进程 CPU 记账跟调度时钟走（约 15.6ms 一格），一天传播不到一格时会读成
`0.00`——那一跑等于没量。所以 `0.00` 时最多重采三次、**取最大值**。
取最大而不是平均：真退化成 60ms 的那次若和两个 0 平均成 20ms，回归就被糊掉了。

## 三、预热做了什么（为什么这不等于放宽）

- `phases`：正式轮之前，把四刻页 + 夜雨页按同一路径完整跑一遍，均值只打日志
  「`[预热轮] 不计分`」，不写截图、不判定；正式轮另开页面，自己必须过全部 17 项。
- `render-budget`：正式轮之前，另开一个页面跑完整测量（静止 4×1s、拖动、前台 4×1s、
  后台 4s、恢复 4s，约 20–25s），读数丢弃后关页；正式轮另开新页并清 `localStorage`，6 项自己过。
- 覆盖的是**进程级一次性成本**：bundle 解码、脚本 JIT、GPU 频率爬升、GPU 进程内
  ANGLE 程序缓存。诚实地说：正式页仍要为自己的 WebGL 上下文编译着色器/上传纹理，
  所以预热吃不掉全部冷启动——`render-budget` 仍有余量在 CI 上偶发红。

## 五、残余风险

1. **CI runner 的软件渲染冷启动本机复现不了**（CI 恢复 26–31 vs 前台 32–38）。本机能复现
   红，但严重程度不同；新判据在 16 核 Windows 上 10 次只红 1 次，CI 上仍需实跑确认。
2. **rAF 判据的分辨力来自相对值**：headless 被 vsync 钉在 59.9，所以真正有信息的是
   「逐秒是否掉下去」。若 CI runner 的 rAF 上限本身是 30，「末秒 ≥ 前台 × 0.9」仍成立，
   但读数会整体变小。
3. **`0.00` 的残留是分辨率边界**：3/20 是三次重采全 0（真低于一格），重采解决不了；
   闸只能抓 ≥50ms 的量级退化（真退回全库扫描是几十毫秒，跨得过刻度）。
4. **预热让闸门变慢**：phases 37–49s → 87–182s；render-budget 45–56s → 63–92s（预热）
   → 84–109s（预热 + rAF 采样）。
5. **`传播的代价随规模走` 偶发 1/30 红**（half 10.57ms vs all 1.38ms），与本次改动无关的
   既有抖动；未改阈值、未跳过。
6. 三道闸共用同一台机器时互相干扰；正式读数请单跑，别和 busy loop 抢核。
