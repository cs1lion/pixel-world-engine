**上游**：`SPEC_DRAFT_20261025.md`（用户与 Claude 五轮 grill 后的结论）、`MIGRATION_FROM_XIAOXI.md`（实测盘点）。

## 1. 问题

旧仓 `cs1lion/xiaoxi` 把像素世界做成了「督办台账的只读投影」。世界的一切都由台账驱动：
一单活从哪来、谁去干、干完算什么，全部经过 commission。世界本身没有自主性，
它的价值被绑在"展示 Agent 干活"上。

用户要的不是这个。用户要的是**世界本身**：一座按自己规律运行的镇子，潮汐涨落、
灯火明暗、居民作息，这些规律本身就是内容。Agent 干活可以是一种输入，但不是主体。

而且这套世界要能换皮：换一套设定集，长出一个完全不同的世界。

## 2. 解决方案

新建独立仓 `pixel-world-engine`，世界优先、规则驱动、可换设定集。

三条支柱：

1. **世界自己跑**。固定步长模拟、潮汐周期、居民作息、灯油衰减，都不依赖外部服务。
2. **规则约束下的生成**。LLM 只能输出白名单内的结构化命令，Schema 过不了就拒收。
3. **记忆是时间线**。按日期 + 人物经历 + 世界事件存成 Markdown，人可读、可 diff。

## 3. 用户故事

1. 作为使用者，我打开页面就能看见一座在动的镇子，不必先下达任何指令。
2. 作为使用者，我能看出潮水在涨在退，而且低处真的会被淹。
3. 作为使用者，我能感觉到居民按自己的作息活动，不是围着我转。
4. 作为使用者，我说一句话，世界按它自己的法则作出反应，而不是无条件照办。
5. 作为使用者，世界拒绝我的时候会说清为什么，而不是默默不动。
6. 作为使用者，我能看见每个角色的灯有多亮，那代表他还有多少油。
7. 作为使用者，我离开一段时间再回来，镇子还是那个镇子，只是过了几天。
8. 作为使用者，我能读到这座镇子过去发生过什么，像读一本编年史。
9. 作为使用者，我能看见某个角色记得我做过什么，而且有据可查。
10. 作为维护者，我换一份设定集配置，就能长出一座风格完全不同的镇子。
11. 作为维护者，我改潮汐周期只改一个配置值，不用碰模拟代码。
12. 作为维护者，LLM 出问题时世界照常运行，只是那句话没被听懂。
13. 作为维护者，我能用一条命令验证世界没跑偏。
14. 作为维护者，我读记忆文件就知道上周发生了什么，不用查数据库。

## 4. 实现决策

### 4.1 仓库布局

```text
pixel-world-engine/
├── world-client/          Phaser 前端（Vite + TS）
│   └── src/
│       ├── world/         模拟内核（不 import Phaser）
│       ├── render/        渲染层（只读快照）
│       ├── ui/            HUD / 神谕栏 / 抽屉
│       └── scenes/        场景装配
├── server/                FastAPI
│   ├── rules/             命令 Schema 与校验
│   ├── events/            事件日志
│   └── oracle/            LLM 造物主
├── memory/                时间线记忆
└── docs/
```

### 4.2 三层规则

| 层 | 内容 | 存放 | 谁改 |
|---|---|---|---|
| **L1 硬规则** | 命令白名单、取值域、数量上限 | `server/rules/schema.py` | 只有开发者 |
| **L2 规则模板** | 可用的命令种类与其参数形态 | 同上，按设定集分组 | 开发者，换设定集时整组替换 |
| **L3 自由描述** | 叙事文本 | 不进世界状态 | LLM 随意 |

L1 的三条铁律（用户 2026-10-25 确认）：
- 潮汐周期抖动 ±2 分钟，不可取消也不可放大。
- 灯油衰减只活在渲染层，不进 `Simulation`。
- 任何命令必须过 Schema；失败拒收并返回错误码，不静默忽略。

### 4.3 命令清单 v1

白名单模式：不在表里的一律拒收。

| 命令 | 参数 | 说明 |
|---|---|---|
| `weather.set` | `value: 'clear' \| 'rain' \| 'storm'` | 天气 |
| `tide.setLevel` | `value: 0.0–1.0` | 潮位；超过硬规则上限被拒 |
| `building.add` | `prefabId, at: {x,y}` | 落一栋楼；位置要过占地校验 |
| `building.remove` | `instanceId` | 拆一栋；有人在里面干活则拒 |
| `miracle.spawn` | `kind: 'light' \| 'tree' \| 'cat'` | 神迹 |
| `npc.setSchedule` | `id, schedule` | 改某个居民的作息 |

### 4.4 潮汐

状态机在 `world/tide.ts`：

- 周期 12 分钟，每次涨落带 ±2 分钟抖动（用确定性伪随机，种子来自世界时间，保证可回放）。
- 潮位 0.0–1.0，映射到世界里的水位高度。
- 低区被淹时，寻路代价上升；居民作息按潮位调整。
- **只做涨/退两档**（用户确认）。波浪与涟漪推迟到 v2。

渲染在 `render/tide-view.ts`：水位图层、淹没区压暗、岸边泡沫。

### 4.5 灯油

在 `world/lampoil.ts`，但**只被渲染层读**：

- 每个角色有一盏灯，亮度 = 灯油余量。
- 余量随时间与活动衰减。
- 亮度低于阈值时，角色渲染发灰、动作帧率下降。
- **`Simulation` 不读灯油**，所以世界的确定性回放不受影响。

### 4.6 事件日志

取代台账。`server/events/log.py`：

- 只增不改。每条事件有 `id / at / kind / actor / payload`。
- 世界侧通过 `world/events-client.ts` 读最近 N 条，投影成世界状态。
- 世界的状态改变也写回日志（`kind: 'world.changed'`），形成闭环。

### 4.7 记忆

`memory/` 目录，Markdown + YAML frontmatter：

```text
memory/
├── entries/2026-10-25.md        每日快照：潮位、天气、大事
├── characters/莞尔.md           单人档案：双面表、作息、与玩家的往来
├── events/E0001-渡口的第一夜.md  单次事件：起因、经过、结果、证据
├── rules/礼仪.yaml              L2 社会规则
└── index.yaml                   索引
```

写入铁律（用户 2026-10-25 确认）：
- **只有 `direct_observation` 能触发写入**。LLM 的角色是「总结观察到的事」，不是「创作回忆」。
- 每条 entry 必须带 `source` 与证据链。
- 没有依据时，宁可不写。

### 4.8 可扩展性

半数据驱动（用户确认 B 方案）：
- **数据化**：色板、瓦片配方、预制体、居民作息、潮汐周期、命令白名单。
- **留在代码里**：潮汐状态机逻辑、灯油衰减公式、寻路、模拟步进。
- 换设定集 = 换一份配置包 + 可能改几个常量，不改引擎骨架。

自进化范围（用户确认 A+B）：
- **A 记忆层**：世界记住玩家偏好。
- **B 规则层**：LLM 根据反馈调整 `rules/*.yaml`。
- **C 结构层**（模型生成新命令 Schema）暂不做。

### 4.9 存档

v3。新增 `tide.level`、`lampOil[id]`、`world_change_version`。
v2 存档自动升级（默认 `tide=0.5`、`lampOil=full`），指纹重算。

## 5. 测试决策

- **好测试的标准**：断言外部可观察行为。世界的单测继续守「`world/` 不 import Phaser」。
- **接缝**：只有两个新接缝——命令校验（纯函数，喂 JSON 断言接受/拒绝）与事件日志客户端（注入 fetch）。
- **潮汐**：给定种子与步数，断言潮位序列可复现。这条是确定性的基础。
- **灯油**：断言它不出现在 `Simulation` 的任何读路径上（用一个源码扫描测试锁住，同 `no-cjk-canvas.test.ts` 的做法）。
- **浏览器回归**：沿用 `scripts/*.mjs` 的形态，但按新 HUD 重写。

## 6. 不在范围内

- 语音、对话、立绘（旧仓的事）。
- 多角色协同（v1 只有一个主角 + 若干 NPC）。
- 记忆检索（MD 到几百条再谈向量）。
- 结构层自进化（LLM 生成新 Schema）。
- 波浪与涟漪动画。
- 旧仓的督办台账、durable、Worker。

## 7. 风险

- **搬迁期两仓并存**。`world-client/src/world/` 与旧仓 `pixel-world/src/world/` 会分叉。
  迁移清单里写清了搬什么，搬完就在旧仓 `pixel-world/` 顶部加一行「已迁移，勿改」。
- **事件日志取代台账**是本仓最大的一次改造。`simulation.ts` 2146 行里所有吃 `sync` 命令的
  地方都要改，且现有 57 个测试里有一批要重写。
- **设定集可换**这个承诺，在第一版只有一套设定集时是纸面的。要有一条测试证明
  「换一份配置能起来」，否则它会退化成口号。
