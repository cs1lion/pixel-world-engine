## 3. 完成度不够的地方（按影响排序）

### 3.1 产出受拍点量化影响（未修，已登记）

粗分帧（5000ms 一拍）比细分帧一天少走半趟作业，于是**同一天跑两次，产出账可能不同**。
这是既有的 `stepIdle` 行为（只在帧边界判 `nextRoutineAt`），不是产出账引入的，
但产出账把它**变成了看得见的数字**。测试里因此只断言「库存不为负」，不断言具体份数。

- 影响：世界「同种子同输入同输出」这条在**分帧粒度**上本来就有缺口，现在有了可观测的后果。
- 建议：单独一轮，把拍点量化摊到 `routines` 的时间线上；不要顺手改，会牵动全部基线。

### 3.2 位图层没有色板闸门

`audit-palette` 只管程序化色板（24 色预算），位图 PNG 一个像素都不查。
`docs/adr/ADR_ART_PALETTE_DECISION.md` 用实测（连续色调，扩槽解决不了）把「扩容」证伪，
诚实地把这条路留成了**人工证据**（`color-deviation.json`），而不是自动闸门。

- 影响：默认开之后，不受预算约束的那一层成了日常画面。
- 建议：要么接受「位图层靠人眼」，要么做一条「每张图的主色数 / 与设定集色板的最大偏差」闸门——
  后者需要先定阈值，别拍脑袋。

### 3.3 A1 口径只定性、没修（用户已拍板）

`schemaPassRate` 恒 1、`manualModificationRate` 恒 0：因为引擎里根本没有「确认结果是拒绝」这个输入。
已按用户拍板走「(3) 改口径不改字段」，写进 `ADR_SCHEMA_PASS_RATE_SEMANTICS` 与测试。
真正的失败侧分母要等「LLM 生成结构被 schema 拒」这条输入出现。

### 3.4 记忆有了产出，但没有去处

她知道今天搬了三趟炭，但不知道那三份炭后来怎样了。消耗现在只是按世界日扣一份，
**没有对手方**（谁烧的、烧来干什么）。这是「作业有了产出」与「世界有了经济」之间最大的一步。

### 3.5 复盘的覆盖面

`docs/OPEN_ISSUES.md` 里 A3 之后的问题（`metrics.ts` 未接线、`relationSymmetryRate` 恒 null 等）
这一轮一个都没动。它们不在用户点名的四件事里，但属于「完成度不够」的同一张清单。

## 4. 用户可能没想到的（值得看一眼）

1. **生图 key 贴在聊天里了**：它现在只在 `server/.env`（已被 `.gitignore` 挡住），
   但它已经出现在对话记录里，建议**换一把**。LLM key 同理，只是没贴出来。
2. **`?art` 默认开之后，旧像素基线不再等于默认画面**：要比对旧基线必须显式 `?art=0`。
   这条写进了 ADR，但下一个改渲染的人未必看 ADR。
3. **`work_note` 每次作业都可能发一次模型请求**：一天 10 次，七个人就是几十次。
   现在有 12s 超时与「同时最多 2 个在飞」的并发上限，但没有**每日预算**。
   真按人天跑世界，这是一笔会漏看的成本。
4. **没有开 PR**：远端分支保护 API 在本仓凭据下 404，所以 main 的边界靠本地
   `.githooks/pre-push`。**钩子没装时保护会安静消失**，`npm run check:hooks` 是必跑读数。
5. **验收的时间成本已经不低**：相位冒烟一次 6m13s，其中四刻各等村民落定约 26 秒
   （既有等待，不是这轮引入的）。再加因果链之前值得先问一句：
   这些验收还能不能在同一分钟内跑完。
