## 一句话

`BRIGHT.shallow` 与 `TERRAIN_COLORS.shallow` 同色（dL* = 0.00），浅滩的亮边是一条隐形线。今天没有任何人看见过它——**莞尔镇一张浅滩格都没有**（灯潮界有，但那份包把 `shallow` 的底色改成了 `moss`，撞对了，不是被守住的）。这不是 bug 报告，是一个待决的调色板决定。

> **2026-10-30 补：** 灯潮界的浅滩底色那天从 `copper` 换成了 `moss`（理由与候选见 `region-paint.ts` 的「浅滩轨道那一处」）。这件事**不改变本文的任何结论**，只改下面几个由它算出来的数：`copper` 时代的读数在原处保留并标了「改色前」，现行读数补在旁边。

（原文这里写「两座已交付世界一张浅滩格都没有」——与同一份文档下面那张表（莞尔镇 0、灯潮界 > 0）自相矛盾，而那条依据由 `test/terrain-edge-invisible.test.ts` 的「登记理由的依据：莞尔镇没有浅滩，灯潮界有」钉着。结论「没人看见过」仍成立，错的是给的理由。）

## 事实（都有测试钉着）

`world-client/test/terrain-edge-invisible.test.ts` 量的是**源色**，不依赖渲染：

| 项 | 值 |
|---|---|
| `BRIGHT.shallow` | `water`（token 名） |
| `TERRAIN_COLORS.shallow`（莞尔镇） | `WORLD.water` |
| 莞尔镇 dL* | **0.00** |
| 灯潮界 dL* | 有落差——那份包把 `shallow` 的底色改成了 `moss`（2026-10-30 之前是 `copper`） |
| 莞尔镇 shallow 格数 | **0** |
| 灯潮界 shallow 格数 | **> 0** |

莞尔镇那 0.00 **今天不构成可见缺陷**：没有浅滩格，就没有亮边可画。灯潮界有浅滩，但它的 `shallow` 底色被包改成了 `moss`，撞对了——**不是被守住的，是撞对的**。

## 为什么单独立项

`terrain-edges.ts` 的 `BRIGHT` 表注释写着「亮一档 token 名：只用现有 24 色里的 `grassLit` / `plaza`。」（这行原来末尾还挂着 `（§1.2「不加色」）`，本文到此为止一直照着那一版引。`1bcb137` 把那个出处删了——`ART_STYLE_TARGET` 从未入库，而规矩本身就在同文件规则 3 里，不需要一份不在仓里的文档替它背书。引文跟着改成现在的原文，**规矩一个字没动**，下面照旧按它推。）`shallow` 现在取 `water`，而 `water` 同时就是浅滩自己的底色——所以这一项在「不加色」的约束下**没有正确答案**。

**这句话是假话，已按实测改写。** 原文在这里写「24 色里再也挑不出一个与 `WORLD.water` 有落差、又适合当水面色高光的 token」，据此推出「这个约束下无解」。实测：`terrain-edges.ts` 文件头规则 3 那张 7 token 清单里，**`trim` 就比 `WORLD.water` 亮，落差 27.87**——压过可辨下限 6 四倍多，比 grass / farm / mud 三条已经在用的亮边（9.51 / 10.82 / 14.42）都醒目。而 `trim` 本来就在册、本来就在那张清单里。实测由 `world-client/test/terrain-edge-invisible.test.ts` 的「浅滩亮边缺色的理由不在 24 色里」钉住，两种改法（`trim` 离开清单、`trim` 变得不比水色亮）都验过会红。

原来把两件事混成了一件：**调色板无解**（假）与**清单里没有一个比水色亮的**（也假，`trim` 就是）。所以原选项 A 建立在一个不存在的前提上。

要么：

- **A. 破例加一个新色**（真违反 `terrain-edges.ts` 规则 3 的「不加色」，需先改 `docs/SPEC_V2.md` §4.2 的「24 色不变」）——已无必要，见上；或
- **A′. 把 `BRIGHT.shallow` 改成清单内已有的 `trim`**。不新增颜色、不动 24 色预算、不违反 `terrain-edges.ts` 规则 3 的「不加色」，也不需要改 `docs/SPEC_V2.md` §4.2。代价只有一条：`terrain-edges.test.ts` 的「边色 token 清单」不会红（trim 早就在册），但 `terrain-edge-invisible.test.ts` 的 `KNOWN_SAME` 双向比对会红在 `gone` 方向——那正是它该有的样子，删掉那一行即可。**这是唯一一个不需要动规范的选项。** 剩下的问题只是审美：`trim` 是暖金色，当水面高光好不好看得盯着屏幕定；或
  - **2026-10-28 补：候选在两套色板上都成立，不是只对一座镇。** `f943b4a` 加了「trim 换到灯潮界的浅滩底色上也够格吗」：`trim` 对 pack 自己选的浅滩底色落差 **32.25**（`copper` 时代；改色后对 `moss` 是 **38.20**），同样比底色亮、同样压过下限 6 四倍多。这不是锦上添花——`BRIGHT` 表存的是 **token 名**不是色值，同一个 token 在两套色板上不是一回事，最现成的反例就是这一项自己：`BRIGHT.shallow = 'water'` 在莞尔镇是 0.00（底色就是它自己），在灯潮界是 **14.32**（`copper` 时代；改色后是 **8.36**）。同一条赋值，一座镇上隐形、另一座上看得见，所以「在莞尔镇合格」推不出「在灯潮界合格」。
  - **三个数各有其主，别混**（这条是我在这轮里自己写错才记下的；括号里是 2026-10-30 改色后的现行值）：pack 的浅滩底色对 **pack 自己的 `water`** 是 **14.32**（今 **8.36**），那是灯潮界 shallow 亮边**当天**的落差；它对 `WORLD.water` 是 **3.28**（今 **2.67**），那才是两套浅滩底色之间的差（低于可辨下限 6，所以「底色换了个色」本身并不显眼）；`WORLD.water` 对 pack 的 `water` 是 **11.04**（今 **11.03**），同一个 token 名解析出的值差这么多，这才是「搬过去可能撞上」的真正原因——**这个数不随浅滩底色变**，它量的只是两个 `water`。
- **B. 改 `TERRAIN_HEIGHT.shallow`**，让浅滩不画亮边（现在 1，与 stone/mud 同）；或
- **C. 维持现状，登记为已知限制**——即当前 `KNOWN_SAME` 那一行。

选 C 的话要接受一件事：**将来谁往莞尔镇加一片浅滩，屏幕上就会出现一条看不见的线**（那处 dL*=0 已在登记表里，`appeared` 不响；它也没修好，`gone` 不响）。原文在这句后面还写着「而没有任何测试会红」——**那半句是假的，2026-10-28 改**：`terrain-edge-invisible.test.ts` 的「登记理由的依据：莞尔镇没有浅滩，灯潮界有」断然断言莞尔镇的 shallow 格数**等于 0**，谁加一片浅滩它当场红，报的是「KNOWN_SAME 那句『肉眼从没看见过』就是假话，回去改注释」。所以 C 的代价比原文说的小：不是无声无息，是会红、但只逼着改注释。这一条已由测试兜住一半——它会逼着改注释，而改注释的时候会重新看见这处 dL*=0。

## 已就位的东西

- `test/terrain-edge-invisible.test.ts`：8 种材质 × 2 套色板的实测落差；撞底色集合与登记表的双向比对（新退化 / 记录过期都红）；登记理由的依据（莞尔镇 0 张、灯潮界 >0）也有桩。
- 「浅滩亮边缺色的理由不在 24 色里」：钉住「规则 3 的清单内正好有一个能用的 token（`trim`）」这个实测事实；`trim` 离开清单、或变得不比水色亮，两种改法都验过会红。
- 「trim 换到灯潮界的浅滩底色上也够格吗」（`f943b4a`）：上面那条只量了莞尔镇，这条补第二套。不重钉 27.87（已经有了，重钉一处的代价是将来要记着改两个地方）。这条断言的期望值是 **38.20**——2026-10-30 换底色时跟着算过一遍，`32.25` 随之作废。
- 合成读数把三个方向各演一遍，闸门不是空的。

## 不属于这个 issue 的

`DARK.shallow` 没这个问题——但原文那句「`DARK.shallow = 'stone'`（stone 比 water 亮）」**两个数都错**：实际是 `'ink'`，而 stone 比 water **暗**（L* 27.84 vs 42.63）。结论仍成立，理由换成对的：`ink` 对浅滩底色 ΔL* = 37.40，压过可辨下限，且暗边本来就该比底色暗。

（**2026-10-30 复核：37.40 这个数当初就算错了。** `ink` L\* 7.97、`copper` L\* 45.91，差是 **37.94**，不是 37.40；改色后对 `moss` 是 **31.99**。两种底色都过下限 6，所以结论一个字不用改——但「结论对」不等于「数对」，这处一并订正。）

grass 亮边曾有一整类不可见，已在别处修掉（取 `plaza`，dL* 9.51）。

## 收口标准

定了 A′ / B / C 之一；若选 A′ 或 B，同步更新 `KNOWN_SAME` 与 `BRIGHT` 表，并让那条双向比对继续全绿。**A′ 不需要改规范**——它不动 24 色预算，`terrain-edges.test.ts` 的「边色 token 清单」也不会红（`trim` 早就在册）。
