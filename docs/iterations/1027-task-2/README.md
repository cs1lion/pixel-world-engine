# 1027 迭代任务 2 · 外环：造物主生成 × 渐进迭代

> 暂存于 2026-10-27。本目录只做「收资料」：把外部设计文档原样收进项目，作为一组迭代目标。**没有任何实现已开始，也不含排期。**

## 这组资料讲什么

「外环」：造物主引擎把设定资料与人类的审美批注，通过可计算的检查门禁，编译成内环可执行的确定性资产与不变式护栏；自治等级（L0–L4）靠自动度量上下调节。与「内环」（世界记忆 × 感知与信息传播，1027 迭代任务 1）互为另一环，两环只以契约相接：内环输出聚合态的世界心电图，外环注入受校验的创世指令。

两份 xlsx 出自同一轮对话（表头自带「来源：上一轮回答」且互相引用）：可行性评估定义角色与指令，自治爬梯定义这些角色各自的等级起点与收敛判据。

### v1.0 对外环的意义

前两份 xlsx 停在「每项能力各自往上爬，具体等级待填」，v1.0 第 3.3 节把它填实了：

| 能力模块 | 起步 | 阶段一目标 | 免审门禁 |
| --- | --- | --- | --- |
| 设定理解 | L1 | L2 | Schema 通过率 100%、冲突数 0、要素覆盖 ≥ 95% |
| 布局与建筑 | L2 | L3（10% 抽检） | 寻路连通 100%、重叠碰撞 0%、空间约束 100% |
| 历史 / 关系 / 记忆 | L2 | L4 | 溯源 100%、关系双向对称 100%、同种子回放哈希一致 |
| 静态美术 | L1 | L2 | 网格对齐 100%、调色板外溢 0%、同类剪影 `IoU ≤ 0.75` |
| 动画 | L0 | L1 | 通用身体帧 + 纸娃娃叠层绕过序列帧；帧间重心偏移 ≤ 1px |
| 导演运行 | L1 | L2 | 不变式违反 0、连续 7 天情绪均值在 `[-0.3, +0.6]` |
| 通用性 | L0 | L2 | 换第二套设定包时**内核与协议改代码行数 = 0** |

熔断线也给了具体数：升级要连续 3 批（或 14 个 `world_day`）自动检查通过率 ≥ 98% 且人工修改率 ≤ 2%；降级触发是单日内摘要校验拒绝率 > 10%、不变式被违反 ≥ 1 次、或人工回滚——任一命中即降回 L1，并把现场存成回归用例。

## 迭代时要回答的问题

1. **先定接口**：可行性评估的结论是「先写设定包 manifest 和创世指令两份规格」——它们是造物主与引擎之间的接口，也是本轮最该先落地的东西。
2. **三层资产解耦**：拓扑骨骼层 100% 确定性（L4）／风格组件层受控生成＋可计算门禁（L2）／叙事沉积层由 Trace 规则驱动（L3–L4）。
3. **指令白名单**：CreateRegion / PlaceBuilding / SpawnCharacter / SeedHistory / InjectEvent，全部经引擎校验后写入事件日志，可回放、可回滚、可审计——与项目「LLM 只能输出白名单内的结构化命令」的定位直接对齐。
4. **收敛四条件**：可计算指标、人工介入留下可复用物、回归集、回滚与分支。缺一条，自治等级就不许往上爬。
5. **两处边界**：审美验收难以完全自动化（等级上限取决于验收标准能否写成可执行检查）；动画与瓷砖接缝的瓶颈可以绕过，但要在目标里写明「完整」的含义被改变了。
6. **边界红线要写进代码，不是写进文档**：v1.0 第 0 节规定造物主六个角色**严禁直接改记忆表或信念表**，一切修改必须封装成 `CreateRegion` / `PlaceBuilding` / `SpawnCharacter` / `SeedHistory` / `InjectEvent` 五条指令并经引擎校验。这条与仓库现有做法一致（`server/rules/schema.py` 是唯一闸门），落地时应有一条测试锁住「造物主没有旁路」。

   > **2026-10-28 补记：「唯一闸门」按字面不成立——仓里有**两份**命令清单，各活着。**
   > 1. `server/rules/schema.py` 的 `COMMAND_CHECKS`（服务端规则层，扁平表，七条命令，
   >    每条带 `_only(...)` 参数白名单与稳定错误码）；
   > 2. `world-client/src/world/intent-schema.ts` 的 `ParsedIntent`（客户端意图层，
   >    十种 `kind`，含 `unknown` 这个一等公民）。
   >
   > 这不影响第 6 条的主张——它想说的是「造物主的修改只能经引擎校验，不许有旁路」，
   > 那句话不需要「唯一」也站得住，而且**两份清单都在正好让「旁路」更难出现**：
   > 服务端拒未知命令，客户端把听不懂的输入编译成 `unknown` 而不是猜一条。
   > 但落地时别照「唯一」去设计：要锁「造物主没有旁路」，两道都得锁，
   > 只在服务端立闸门的话，客户端意图层仍然是空的。
   > 详见 `docs/SPEC.md` §4.3 的 2026-10-28 补记（同一个错误的完整记录）。
7. **导演只吃四个标量**：`mean_valence`、`mean_arousal`、`info_entropy`、`isolated_holders_count`。导演不许读全量日志——这条决定了两环之间的接口长什么样，也决定了内环必须真的把这些统计吐出来（见任务 1 的 `DayClosed` 快照）。
8. **✅ 一天有多长：已定，采用 24 世界小时**（2026-10-27，与任务 1 同一条）。v1.0 的 `day_length_seconds`（900 秒）按 `86400` 秒读，`DAY_MS` 不变；900 / 3600 改为「现实里看完一天要多久」的节奏目标，由 `timeScale` 承担（96 / 24，现状默认 6、上限 60）。外环的「连续 14 个 `world_day`」「连续 7 天情绪均值」因此有了确定的长度：14 个世界日 = 14 × 24 世界小时，与跑多快无关。
