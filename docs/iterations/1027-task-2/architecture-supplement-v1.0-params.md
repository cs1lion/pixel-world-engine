# 像素世界引擎 · 补充架构设计与全量待定参数规格书 v1.0

> **文档定位**：本文档为《世界记忆协议 v0.1》、《单位间感知与信息传播设计》、《造物主引擎：可行性评估》及《渐进迭代：自治等级与收敛条件》四份核心文档的**跨层咬合补充与待定参数定稿规格**。
> 
> **核心哲学守则**：
> 1. **真相与视图分离**：事件日志（Event Log）是唯一真相，LLM 只负责“理解”与“提议”，严禁直接充当状态存储。
> 2. **结构同构，语义绝缘**：上游 Agent 的隐私业务数据在进入像素世界前，必须剥离敏感名词，仅将“工作流拓扑、阻力与情绪效价”编译为像素世界的本土叙事。
> 3. **人的注意力是终极稀缺资源**：验证必须左移。人类在 Review 中只做直觉裁决，由机器将裁决逆向编译为可计算的源头规则与不变式护栏。

## 0. 双任务组调用边界锁（Task Group Boundary Lock）

当本文件被同时全量挂载至两个独立任务组时，各组必须严格遵守以下职责红线，严禁跨界实现：

* **【任务组 A：世界运行时内核（记忆 + 感知传播）】**
  * **主责范围**：实现《世界记忆协议 v0.1》、《单位间感知与信息传播设计》及本文档 **第 1 节、第 3.1 & 3.2 节**。
  * **边界红线**：除日终摘要（每个 Holder 每天 ≤ 1 次）与屏幕内关键对话外，**写入、检索、传播路径保持 0 次模型调用**；单位逻辑严禁读取全局状态，只能通过感知 API 读写局部记忆与信念库；仅预留接收 `source = agent / genesis` 事件的入口，并在 `DayClosed` 时向外抛出统计快照，**绝不实现任何造物主或导演的生成逻辑**。
* **【任务组 B：造物主生成与控制迭代（造物主 + 自治爬梯）】**
  * **主责范围**：实现《造物主引擎：可行性评估》、《渐进迭代：自治等级与收敛条件》及本文档 **第 2 节、第 3.3 节**。
  * **边界红线**：造物主各角色（解读者/美术监督/地图师/史官/导演/审校）**严禁直接修改底层记忆表或信念表**；所有对世界的修改必须封装为受校验的 `创世指令`（如 `CreateRegion`、`PlaceBuilding`、`SpawnCharacter`、`SeedHistory`、`InjectEvent`），经引擎校验通过后转化为标准 `Event` 进入世界。

## 1. 第一组补充设计：记忆 × 感知传播（运行时叙事与认知层）

### 1.1 「认知失调 → 主动求证」的行为闭环（Belief-to-Action Bridge）
打通《信息传播设计》中的“去核实 / `RumorDebunked`”与《世界记忆协议》中的行为决策 Modifier，用纯规则驱动像素小人的空间求证跑位：

1. **冲突检测**：当单位收到 `ClaimTold`（准备生成 `source_mode = heard` 的记忆）时，检索自身记忆库中是否存在相同 `event_refs` 或同地点同日（`place_id + day`）的高置信度记忆（`witnessed` 或 `confidence ≥ 0.8`）。
2. **求证冲动计算（纯规则，0 模型调用）**：
   若新旧断言的情绪效价方向相反（`valence_new * valence_old < 0`）或结果冲突，计算求证冲动值：
   `verify_impulse = salience * abs(valence_new - valence_old) * speaker_trust`
3. **空间求证与辟谣演出**：
   * 当 `verify_impulse ≥ 0.45` 时，听者状态设为 `存疑（suspicious）`，并向行为决策层注入高优日程 Modifier：**前往事发地 `place_id` 查看痕迹，或前往 `公告栏 / 档案室` 核对**。
   * 单位抵达事发地触发 `CueFired` 并读取现场 `Trace`（或读取官方公告 `AnnouncementRead`）后，若证实传言为假，立即向原传播链发出 `RumorDebunked` 事件，并将造谣者的信息源可靠度（`credibility`）下调 `0.15`。

### 1.2 「空间沉积（Trace） → 溯因推断（Inferred Claim）」规则查表
为《世界记忆协议》第 4 节的 `source_mode = inferred` 与《信息传播设计》第 5 类通道“痕迹（低保真，需推断）”提供 0 模型调用的确定性桥接：

| 建筑/地点痕迹 (`Trace.layer_type`) | 路过触发 `CueFired` 生成的 `inferred` 记忆内容 (`content.what`) | 初始 `detail_level` | 初始 `confidence` | 情绪倾向 (`valence` / `arousal`) | 后续传播倾向 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **焦痕 / 坍塌** (`scorch / damage`) | “此处近期似乎发生过严重的事故或冲突” | `1`（缺省 `who`） | `0.35` | `-0.6` / `0.7` | 高 `surprise`（`0.8`），驱动小人去酒馆打听“是谁干的” |
| **紧急修补** (`patch`) | “这里的设施刚经历过抢修” | `1`（缺省 `who`） | `0.40` | `-0.2` / `0.4` | 中等显著度，仅向同工坊同事询问 |
| **花环 / 彩带** (`garland`) | “这里刚刚举办过一场庆典或嘉奖” | `1`（缺省 `who`） | `0.50` | `+0.7` / `0.6` | 正向传播，提升路过者的情绪基准 |
| **磨损小径** (`worn_path`) | “最近有人频繁往返于这条路线” | `1`（缺省 `who`） | `0.30` | `0.0` / `0.2` | 低显著度，仅作为环境背景记忆 |
| **碑文 / 留言牌** (`inscription`) | 直接读取碑文绑定的 `event_ref` 摘要 | `2` | `0.90` | 继承原事件 | 高保真转化，直接升级为 `source_mode = read` |

### 1.3 上游 Agent 事件的「隐喻脱敏编译器」（Sanitized Metaphor Compiler）
严格落实《世界记忆协议》第 14、15 节要求：当上游 Personal Agent 的任务带 `visibility = private_to_player` 进入世界时，在边界网关处销毁一切真实文件名、人名与业务文本，仅提取 **`[任务拓扑类型 + 耗时/重试次数 + 最终状态]`** 编译为 `visibility = sanitized` 的世界事件：

| 上游 Agent 原始动作 (Private) | 编译后的世界 Event (`kind` & `place_id`) | 结构化 `outcome` (Sanitized) | 世界内衍生的记忆、痕迹与传言表现 |
| :--- | :--- | :--- | :--- |
| 外部检索 / 抓取网页成功 | `kind: expedition_done`<br>`place_id: place_watchtower` | `{harvest: "发光矿石", difficulty: "normal"}` | 斥候记下顺畅出征；哨塔积累物资痕迹 |
| 代码执行 / 工具调用连续报错重试 | `kind: workshop_accident`<br>`place_id: place_foundry` | `{obstacle: "炉温失控", retries: N}` | 铁匠记下高挫败感片段；工坊生成 `焦痕`；酒馆流传“铁匠铺昨晚炸炉了” |
| 挂起等待人类授权 (HITL) | `kind: oracle_prayer`<br>`place_id: place_altar` | `{wait_ticks: T, urgency: "high"}` | 负责小人在祭坛等待；路过村民记下“有人在祭坛虔诚祈祷神谕” |
| 人类在 Review 面板一键准奏通过 | `kind: celebration`<br>`place_id: place_altar` | `{blessing: "golden_seal"}` | 参与者获得高正效价强化（或 `flashbulb`）；工坊挂起 `花环`；贴出官方日报表扬 |
| 人类在 Review 面板批注打回重修 | `kind: discipline`<br>`place_id: place_altar` | `{lesson_id: "rule_hash"}` | 当事小人记下高 `arousal` 训诫记忆，行为 Modifier 立即生效（避开错误做法） |

## 2. 第二组补充设计：造物主生成 × 控制迭代（构建管线与自治爬梯）

### 2.1 收敛条件 2 落地：「逆向审校合成器（Diff-to-Rule Synthesizer）」
为了让“每次人工介入都留下可复用的东西，使人工修改率逐轮下降”不沦为需要人类手写规则的负担，在人工确认点后置挂载逆向合成流：

1. **静默捕获差异（Capture Diff）**：
   当某项能力处于 `L1` 或 `L2 异常拦截` 时，系统记录 `(Agent_Proposal, Human_Final_Commit)` 的结构化 Diff（而非纯文本对比）。
2. **三类规则自动归因与提炼**：
   * **美术资产驳回/微调** $\rightarrow$ 自动提取被拒图的色板外溢色值、孤立噪点或尺寸偏差，更新《美术监督》的量化检查脚本参数或参考图负样本库。
   * **地图布局挪动** $\rightarrow$ 提取被人类手动挪动的建筑对（如将 `铁匠铺` 移近 `河流`），合成为《地图师》的硬性空间约束断言：`assert distance(foundry, river) <= 3`。
   * **设定/台词/历史删改** $\rightarrow$ 提炼为《世界圣经》的禁止项（Negative Invariant）或词汇黑名单，写入对应角色的提示模板与《审校》规则集（更新 `ruleset_version`）。
3. **回归集试跑与一键加冕**：
   新合成的候选规则先在历史回归集（Regression Suite）上静默试跑；若未破坏既有通过项，则在界面底部以单行轻提示询问人类：*“已将您刚才的修改提炼为自动审校规则 #R14，是否启用以实现同类情况免审？”* 人类点击确认即完成从 `L1` 向 `L2` 的爬梯积累。

### 2.2 自治爬梯（L0–L4）的「双向熔断与自动降级机制」
自治等级不是只升不降的单行道。为防止长程运行中的累积漂移，建立基于滑动窗口指标的熔断器（Circuit Breaker）：

* **升级条件（Climb Up）**：连续 `3` 个迭代批次（或连续 `14` 个 `world_day`）在回归集与线上运行中，**自动检查通过率 ≥ 98%** 且 **人工事后回滚/修改率 ≤ 2%**，系统允许将该模块自治等级上调 1 级（如 `L1 → L2` 或 `L2 → L3`）。
* **熔断降级条件（Drop Down）**：
  当处于 `L2/L3` 的模块在单个 `world_day` 内出现以下任一异常：
  1. 《世界记忆协议》日终摘要实体校验拒绝率 `> 10%`；
  2. 世界不变式（World Invariants）被违反次数 `≥ 1`；
  3. 人类主动触发了分支回滚（Rollback）。
  **熔断动作**：立即将该模块实时降级回 **`L1（生成后人工逐项确认）`**，并将异常现场自动保存为回归集的新测试用例（防复发）。

### 2.3 跨组咬合：以「记忆与传播心电图」驱动低频导演（Director PID Loop）
《造物主引擎》中的 `导演` 角色严禁直接读取全量事件日志拍脑袋生成剧情。每天 `DayClosed(day)` 触发日终整理后，由第一组运行时向第二组 `导演` 推送一份仅包含 4 个标量的**世界心电图快照（World Vital Signs）**：

1. `mean_valence`（全村近 3 日记忆情绪均值，范围 `-1 ~ +1`）
2. `mean_arousal`（全村近 3 日记忆兴奋度均值，范围 `0 ~ 1`）
3. `info_entropy`（当日活跃传播的独立 `Claim` 数量与覆盖率方差）
4. `isolated_holders_count`（连续 3 天无任何 `ClaimTold` 交互的孤立单位数）

**导演受控注入规则**：
* 当 `mean_arousal < 0.25`（世界陷入死寂与机械重复）时 $\rightarrow$ 导演提交 `InjectEvent(kind: "visitor_arrival" | "weather_anomaly")` 制造新话题线索。
* 当 `mean_valence < -0.45`（连续高强度任务报错导致全村情绪低迷）时 $\rightarrow$ 导演提交 `InjectEvent(kind: "tavern_feast")` 集中修复情绪效价。
* 所有注入指令必须先过《审校》角色的不变式检查，再作为标准 `Event` 进入世界。

### 3.2 《单位间感知与信息传播设计》通道矩阵与护栏参数定稿表

#### A. 五类信息通道参数表（填补原表「容量」与「权限」待定项）

| 通道类型 | 谁能接收 | 延迟 | 保真度 | 容量（定稿初值） | 权限（定稿初值） |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **直接感知** | `perception_radius` 内且无遮挡的在场者 | 即时 (`0 tick`) | 最高 (`detail_level = 3`) | **无限**（凡在场必判定） | 遵循事件 `visibility`（`private_to_player` 自动转脱敏隐喻） |
| **交谈** | 一对一或酒馆小群（距离 `≤ 2` 格） | 相遇时 | 逐跳衰减 (`每跳 detail_level - 1`) | **单次交谈最多传递 `2` 条 Claim** | 需双方关系 `trust ≥ -0.2`；带 `secret` 标签的断言需 `trust ≥ 0.7` |
| **广播** | 经过公告栏（`≤ 4` 格）或听到钟声的全村单位 | 取决于载体 | 高，有权威 (`confidence ≥ 0.9`) | **公告栏同时最多张贴 `5` 张**（含每日 1 张日报） | 仅限**玩家（神明）、村长（Planner）、系统日终日报**可发布 |
| **书面** | 前往档案室/邮局主动查阅的特定单位 | 慢（跨天） | 最高，持久（不随跳数衰减） | **单封信件 `1` 条 Claim；单本日记 `3` 条/天** | **信件**：仅发件人与收件人可读；**日记**：仅本人可读；**档案**：学者与村长可读 |
| **痕迹** | 路过该建筑（`≤ 3` 格）且触发 `CueFired` 的单位 | 随机 | 低 (`detail_level = 1`，需查表推断) | **每个建筑最多显式暴露前 `3` 个高强度 Trace** | 公开可见（`world` 或 `sanitized`），任何路过单位均可感知 |

#### B. 传播护栏与评测指标定稿表（填补原表「取值/目标」待定项）

| 类别 | 项目 | 说明 | 定稿取值 / 验收目标 |
| :--- | :--- | :--- | :--- |
| **参数护栏** | **扇出上限 (`max_fanout`)** | 单个单位就同一条 Claim 每天最多向几个人主动提起 | **`3` 人 / 天** |
| **参数护栏** | **每次交谈的话题数 (`topics_per_chat`)** | 限制单次交谈传递的断言数量 | **`2` 条 Claim**（按 `salience × relevance` 排序取前 2） |
| **参数护栏** | **冷却 (`pair_cooldown`)** | 同一对单位之间就同一话题传播的最小间隔 | **`1` 个 `world_day`**（日常闲聊整体冷却为 `0.25 day`） |
| **参数护栏** | **最大跳数 (`max_hops`)** | 断言可传递的最大转手层数 | **`3` 跳**（第 3 跳后 `detail_level` 降至 `0`，禁止继续向外转述） |
| **参数护栏** | **每跳保真衰减 (`fidelity_decay`)** | 每传一跳降低的细节层级与可信度折扣 | **`detail_level - 1`**，且 **`confidence × 0.80`**，情绪 `|valence| × 1.10` |
| **评测指标** | **覆盖率曲线 (`coverage_curve`)** | 单一重大事件在村落中的知晓比例随时间变化 | **第 1 天末 `≤ 35%`**，第 3 天末达到稳态 **`60% ~ 80%`**（严禁第 1 天 100% 全知） |
| **评测指标** | **保真度衰减 (`fidelity_curve`)** | 断言平均细节层级随跳数的衰减斜率 | `Hop 0 = 3.0` $\rightarrow$ `Hop 1 = 2.0` $\rightarrow$ `Hop 2 = 1.0` $\rightarrow$ `Hop 3 = 0.0` |
| **评测指标** | **获知时延对比 (`latency_ratio`)** | 官方公告与民间传言触达半数人口的时延比 | **官方公告 `≤ 0.5 day`** vs **民间传言 `1.5 ~ 2.5 days`** |
| **评测指标** | **溯源率 (`traceability_rate`)** | 每条记忆与断言能通过 `event_refs` 追到真实事件的比例 | **`100%`**（硬性红线，任何无源断言直接触发断言测试失败） |
| **评测指标** | **每日传播开销 (`daily_prop_cost`)** | 每天传播与日终整理所消耗的模型调用与计算耗时 | **传播计算 `0` 次 LLM 调用（纯图算法 `< 10ms/天`）**；日终摘要每个重要角色 `≤ 1` 次/天 |
