## 已定的口径

v1.0 与仓库代码撞车的地方，定过一条：**一天 = 24 个世界小时，采用仓库的 `DAY_MS`**（2026-10-27）。v1.0 的 `day_length_seconds = 900` 因此按 `86400` 秒读，900 / 3600 降级为「现实里看完一天要多久」的节奏目标，交给前端时间倍率（`timeScale` 96 / 24；现状默认 6、`?speed=` 上限 60）。两组 README 的第 8 条记录了完整理由。

这条不是新决定，是沿用已有的：`docs/adr/ADR_MEMORY.md` 早已把「一天 = 24 个世界小时」定死（`GLOSSARY.md` 的「世界日序号」同义），前端 `world/lampoil.ts` 的 `LAMP_DAY_MS` 也是 24 小时——同一个长度在仓库里写了好多遍，本身就是把 24 小时当既定事实。所以 v1.0 的 900 秒只可能读成节奏，不可能是另一套「天」。

**这个数写了几遍，不在这儿手写。** 这里原来写的是「三处各写一遍」，并列了 `ADR_MEMORY.md`、`GLOSSARY.md`、`lampoil.ts` 三个名字——那个数是假的，那份名单也是漏的：它漏掉了上一行刚刚让读者「采用」的 `DAY_MS` 本身。2026-10-28 复核，**写这个长度的地方是五处**：

| 位置 | 写法 |
| --- | --- |
| `server/memory/snapshot.py:27` | `DAY_MS = 24 * 60 * 60 * 1000` |
| `world-client/src/world/memory/config.ts:26` | `DAY_MS = 24 * 60 * 60 * 1000` |
| `world-client/src/world/lampoil.ts:27` | `LAMP_DAY_MS = 24 * 60 * 60 * 1000` |
| `docs/adr/ADR_MEMORY.md:24` | 文字：「一天 = 24 个世界小时」 |
| `GLOSSARY.md:32` | 文字：「一天是 24 个世界小时」 |

前三处是代码常量，由 `world-client/test/memory-day.test.ts` 钉住一致（服务端那份是从源码读出来的，不是再抄一个数）；后两处是散文。散文那两处没有闸，所以**这一条本身也会漂**——要复核就重新数一遍，别信这张表。
