## 4. 帧率

### 4.1 旧口径（`render-budget` 闸门内，同机位同状态，各两轮）

| 组 | 静止 | 拖动 | 后台 |
| --- | --- | --- | --- |
| 分支 4.2.1 | 52.4 / 50.8 | 59.6 / 50.7 | 11.0 / 11.0 |
| main 3.90.0 | 60.5 / 50.8 | 58.6 / 53.9 | 11.0 / 11.0 |

> 同组合两轮 52.4/50.8（分支）与 60.5/50.8（main）说明抖动比可能的影响还大，所以"分辨不出差异"不等于"没有掉帧"。

这段读数不能写成「帧率无下降」：两轮之间的离散度本身就把可能的影响盖住了，只能记成「分辨不出」。

### 4.2 新口径（可复现取样，`scripts/fps-protocol.mjs`，不进闸门）

固定条件：世界时刻钉在 12:30（`freezeWorldClock()` + `pinShotState(750min, tide=0)`，采样期间不推进）；
相机钉在 (832,512)、zoom 2；角色与痕迹一并钉住；每格采样 4000ms，丢弃首个 1000ms 窗，
其余窗按 rAF 间隔中位取 fps，再取窗中位；每轮依次测静止 / 拖动 / 后台，跑 6 轮，把读数写到仓外目录（文件名 fps-protocol.json，不入库）。
后台沿用闸门口径（`advanceCount` 每秒推进数）：无头 Chromium 里覆盖 `visibilityState` 不会真的掐 rAF（实测仍 59.9）。

实跑两轮（同一机位、同一钉住状态，Phaser 4.2.1）：

| 调用 | 静止 | 拖动 | 后台 |
| --- | --- | --- | --- |
| run1（6 轮中位） | 59.9 | 59.9 | 11.0 |
| run2（6 轮中位） | 59.9 | 59.9 | 11.0 |

跨轮统计：静止 / 拖动 / 后台的 p10 = p90 = 中位，极差 0.0，**相对离散度 0.0%**；
两次调用逐格相同。读数在仓外 pwe-fps 的 run1、run2 两个目录里，文件名同为 fps-protocol.json。

**这组读数到底能说明什么**：`59.9 / 59.9 / 11.0`、极差 0.0 的真实含义是**这套尺子贴 60Hz 截顶、量不出 1/60 秒以下的差别**，它能回答"两次测量是不是同一条件"，不能回答"引擎变重了没有"。

**读法与限制（如实记录）**：在「同机位 + 世界不可推进」下，旧口径那 50–60 的抖动不再出现，
说明那部分抖动来自世界状态、预热与采样窗口，而不是状态内噪声；但这台机器上静止/拖动贴着
60Hz 截顶，**新指标对「小而短的真实掉帧」分辨力受截顶限制**——以后要拿它比较引擎差异，
需要换成帧间隔分位数 / 长帧计数 / 单帧 GPU 耗时这类指标（见 OPEN_ISSUES F2），
或在有负载的场景、解除 vsync 下再跑；本指标暂不进任何闸门。
