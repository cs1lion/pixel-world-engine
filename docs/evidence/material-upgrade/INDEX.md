# 材质层升级证据（material-upgrade）

本目录是 `feat/material-upgrade` 分支的可复现证据：四类材质（路面 / 空地·广场 / 房屋外立面 /
人物）在**同一机位、同一帧号**下的前后裁图与像素读数。所有图都在本仓内，不引用仓外临时目录。

## 怎么复现

```bash
# 1) 该分支的 dev server（不要用 5188：那是别的工作树的端口，串台过两次）
cd world-client && npm run dev -- --port 5191 --strictPort

# 2) 抓前后两套；标 sheet 的取景点写在 material-capture.mjs，裁图坐标写在 material-analyze.py
node scripts/material-capture.mjs --label before     # 需在基线代码上跑（git stash 后再跑）
node scripts/material-capture.mjs --label after
python scripts/material-analyze.py before
python scripts/material-analyze.py after             # 顺带产出 ../compare/<目标>.png
```

- **取景**：`material-capture.mjs` 只拍整幅画布（480×320 世界像素 = 960×640 CSS），记下
  `scrollX/scrollY` 与 `cssPerWorld`；裁切在 Python 侧按**世界坐标**做。取景坐标只有一处，
  前后两遍必然逐像素对齐（相机 `centerCameraOn` 会被世界边界夹住，靠实际 `scroll` 换算）。
- **帧号**：脚本把 `requestAnimationFrame` 的 dt 固定为 1/60，并跑到第 240 帧再截。
  村民姿势、摊位火光相位因此逐像素可复现。
- **叠层**：只 `display:none` 顶栏/小地图/调试面板，**不改画布尺寸**（Phaser 监听 resize，
  改尺寸会重排取景）。
- **1× 可见性**：`road-wide`（160×96）、`road-band-wide`（160×32，只看铺装带）、
  `ground-wide`（160×64，正好压满 plaza 带 4 格高）三个窗口**不放大**；
  `compare/*-1x.png` 是左右各一半的 1× 拼图。3× 图只用来核对细节，不能代替 1× 判断。
- **BUG-1 复核**：`boiler-base` 工作表（相机 504,276）把炉底入口压在 stone 带上，
  楼脚石基与相邻 stone 地形同一帧可比；见 `bug1-stone-base-vs-terrain-8x.png`。

**煤渣（ground-coal）换了取景**：上一版窗口 (880,700) 里有一处摊位火光/蒸汽在动，
前后两遍会差 31 个像素（读数被污染）。这一版挪到 (850,700)，只取煤渣地本身；
前后两遍同机位同帧，读数差不再含动效。

口径：

- `textureEnergy` = 相邻像素亮度差的平均；平涂趋近 0，有接缝/纹理才抬升。
- `edgePct` = 亮度差 > 3 的相邻对占比，衡量结构线密度（防「脏、花」的抓手）。
- `逐格重复` = 按 16px 整格切分后不同格的个数 / 总格数；`9/9` 即每格都不一样。
- **`onToken` 在灯潮界一律 0%**：昼夜叠色把整片像素挪出了 palette 闭集，精确色槽匹配
  只对默认世界有效（`wall-default` 95.9%）。所以灯潮界的读数不看 `onToken`，
  看相邻差（`textureEnergy` / `edgePct`）与逐格重复率。

## 1× 可见性（2026-11-04 补测）

验收看的是正常缩放，所以另开三个**不放大**的窗口（3× 图不算数）：

| 窗口 | 尺寸 | 颜色数 | textureEnergy | edgePct | 逐格 |
| --- | --- | --- | --- | --- | --- |
| road-wide（含店面上半截） | 160×96 | 79→101 | 7.57→8.06 | 22.45→24.54 | 60/60→60/60 |
| road-band-wide（只看铺装带） | 160×32 | 43→55 | 9.51→9.58 | 33.93→34.95 | 20/20→20/20 |
| ground-wide（plaza 带满格） | 160×64 | 27→36 | 4.13→6.27 | 15.66→24.53 | 35/40→40/40 |

对照图：`compare/road-wide-1x.png`、`compare/road-band-wide-1x.png`、
`compare/ground-wide-1x.png`（左 before / 右 after，都是 1× 原尺寸）。

结论：

- **广场**：1× 能读出来。石面磨痕 + 0–2px 错缝 + 骨料，edgePct +8.87pp；
  左右拼图并排时一眼能看出右半「是铺过的石头」，且 40/40 每格不同。
- **路面**：1× 能读出来，但只到「缝不是一条直尺线」这一档（edgePct +1.02pp、
  textureEnergy +0.07）。这一轮只动了三件被允许的事：
  1. 横缝落位每格错 0–2px（缝的**位置**，暗像素数量不变）；
  2. 每 3–4 格落一枚 2px 浅/深**骨料**（石粒**密度**）；
  3. 广场石面的 2px 磨痕（同上，只落在 plaza）。
  缝深（`stone 0.55`）与受光唇（`plaza 0.28`）的 alpha 一律没动——
  上一轮实测 0.18 会把列 ΔY 从 10.8 压到 5.6、暗带拉到 4.6 格。继续加深就会动
  `lamp-band` 的采样带，按约束停在这一档。

## plaza 逐格 9/9 的撞脸定位与修法

`plaza-ground` 的 48px 窗中心是 (120,496)，起点 (96,472) 是**半格错位**：
窗口的 16px 切分不是 tile 边界，一个「格」实际是
`tile(7,30) 的下半 8 行 + tile(7,31) 的上半 8 行`，相邻一格是 x=8 的同一对半格。

改前逐像素比对的读数：

- `tile(7,30)` 下半 8 行 == `tile(8,30)` 下半 8 行
- `tile(7,31)` 上半 8 行 == `tile(8,31)` 上半 8 行
- 所以两个 16×16 窗口完全相同 → 9 格里只剩 8 个不同的脸。

为什么调石粒 salt 拆不开：石粒（`sh2 % 3`）与苔（`(h+i*7) % 5`）都落在**另外**
半格，撞脸的这半格只有石块的底边/顶边倒角，图案由 `h % 3` 选中的 layout 决定；
两格的 layout 恰好相同。换 `hash2` 的 salt 只会挪石粒，不碰这半格。

修法：只给 plaza 加一道石面中部的 2px 磨痕，取参换一根独立轴
`hash2(x*19 + i*7, y*23 + i*11)`，落在石面内部、正好穿过撞脸的那半格；
其它布局/倒角/石粒/裂纹参数一律不动。复测 `plaza-ground` 回到 **9/9**，
`ground-wide` 从 35/40 变 **40/40**。

## 确定性读数

`node scripts/material-determinism.mjs after` 把 `performance.now` 钉成常量、帧号停在 240，
再隔 1 真实秒截第二张；另开一页跑到同一帧号截第三张。

| 项 | 本分支 | 基线 `39cff04` |
| --- | --- | --- |
| 冻结世界 1 真实秒：全画面帧差 | 0/614400 = 0.00% | 0.00% |
| 冻结世界 1 真实秒：ROI（480×320）帧差 | 0/153600 = 0.00% | 0.00% |
| 同上两张的 sha256 | 相同（`ddfc0f64…`） | 相同 |
| 同一帧号两遍运行 | 1216/614400 = 0.20% | 1080/614400 = 0.18% |

「同一帧号两遍运行」的 0.20% 是**引擎既有**的：载入期有 `Date.now()` 参与种子，
两遍会有同量级的散布，基线是 0.15–0.18%。材质层本身没有引入任何时间/随机源
（全部由 `hash2`/`seedOf` 派生、烘焙在载入期一次完成）。

## 约束读数（本机实测，同机位前后对比）

| 项 | 基线 `39cff04` | 本分支 |
| --- | --- | --- |
| 默认世界 noon 指令 / Graphics（`check-render-budget` 机位） | 15482 / 27 | 15482 / 27 |
| 灯潮界 noon 指令 / Graphics（固定机位探针） | 16747 / 49 | 16875 / 49 |
| 灯潮界黄昏+雨 指令（固定机位，上限 29000） | 21182 / 49 | 21286 / 49 |
| `debugLampPool`（灯亮满潮） | 2552 | 2552 |
| `lamp-band` 覆盖 / 最长暗带（主态） | 75.9% / 3.9 格 | 75.9% / 3.9 格 |
| `lamp-band` 2 格 ΔY | 0.54 pp | 0.54 pp |

三条必须说清的口径：

1. **`lamp-band` 在本机不是常量，是三态**。把两处渲染改动 `git stash` 回 `39cff04`
   连跑 3 次，得到 `75.6% / 4.6 格`、`75.9% / 3.9 格`、`76.9% / 1.8 格` 三种读数；
   改后连跑 3 次得到 `75.9 / 3.9`、`75.6 / 4.6`、`75.9 / 3.9`。任务书的
   **76.9% / 1.8 格是其中之一**，不是稳定值。判据因此改成「同一态逐项相等 +
   三态集合不新增」，而不是「每次都必须是 76.9」。`2 格 ΔY 0.54pp` 与
   `debugLampPool 2552` 两版都复现。
2. **灯潮界指令口径**：上一版 INDEX 的 `16686 / 21014` 是另一个机位；
   这一版按「同机位 before/after」重测：noon `16747→16875`、
   黄昏+雨 `21182→21286`，差值 **+128 / +104** 才是 1× 补测的代价
   （磨痕与骨料加在常驻 Graphics 上）。地形烘焙仍是 0 每帧。
3. **默认世界不变**：`15482 / 27`，与基线同；2026-11-04 这一轮没有碰默认世界的材质。

## 材质 BUG-1 复核（结论：不成立）

上一份材质报告说「`drawWall` 用全局 `paletteFor()`，灯潮界预制楼石脚会取莞尔镇 stone」。
本轮复核**推翻了这条**：

- 运行时探针（页面内 `import('/src/world/theme.ts')`）在灯潮界读到
  `paletteFor().stone = 0x52666a`（灯潮界），`paletteFor('default').stone = 0x3e433f`；
- 同帧裁图里，楼脚石基 3px（world y269..271）与紧邻的 stone 地形同色：
  两段都是 `#476565`（600px / 2640px 的众数，见 `bug1-stone-base-vs-terrain-8x.png`）。

所以 `paletteFor()` 省略参数取的是**当前激活世界**，建楼发生在 `activateWorld` 之后，
不存在串味。详见 `docs/BUGS_FOUND.md` 的「材质 BUG-1」。这一轮没有改 `theme.ts`。
