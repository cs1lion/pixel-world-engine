一件 = 一格（4 件在 (4,25) (5,25) (8,25) (9,25)）。不是一件带 length 的长条， 因为 depth 必须按行算（world-client/src/render/scenery-depth.ts）：一根跨多格的长条 只有一个 depth，就没法与站在不同行的人分别判前后。

一张纹理贴 4 次。四段内容逐格相同，各烘一张就是 4 次 generateTexture 加 4 张 纹理在渲染器里来回切——这正是 N 节「代价」那条警告过的（件数上去会变成多次纹理切换）。 所以纹理只烘一张（bakeTexture），四件各自 add.image 复用同一个 key。

2. 为什么只做东西向（这一笔的结论）

南北向的栅栏在这套投影里读不出来。 这不是省事，是四种画法都试过之后的结果：

# 画法 1:1 下的读法
v1 2px 单线 + 每格一根 4×4 立柱 一根带节的木杆
v2 立柱改成每两格一根、侧面换木色暗面 一根木杆，节更稀
v3 加宽成 5px 带（地影 / 暗面 / 栏杆 / 受光棱） 一根木条躺在地上
v4 2px 线 + 往右下错位 2px 的地影 一根立起来的木杆，仍不是栅栏

原因在几何上：这套投影里「走向」和「高度」都落在屏幕竖直方向。一道沿南北跑的 栅栏，栏杆在屏幕上是竖线、立柱在屏幕上也是竖线，两者平行，谁遮谁都分不出；能用的 只剩「线的两侧一亮一暗」和「错位地影」这两条弱线索，撑不起「一排竖直的立柱」。

东西向就没有这个死结：立柱竖着站、栏杆横着跑，两者正交，「立着」这件事一眼读出来。 所以栅栏只落在两列花床的南端面（人从南口进来先看到的那一面），把通道口收住。 南北向的长栏一件没做——「夹道」这一点只兑现到通道口的两段矮栏，如实记账。

废稿与成品都在 world-client/tmp/garden-stone/fence{1,2,3,4,5}.png（未跟踪）。

3. 与石灯籠的前后关系

栅栏与石灯籠都在 (4,25) 这一行上，取同一个 sceneryDepth，同 depth 时谁在前只剩 创建顺序。pack.ts 里栅栏写在石作之前，于是石作压住那一段栏杆——栏杆从 竿两侧的透明缝里露出来，读成「从石灯背后穿过去」，不是「从底座中间穿过去」。 反过来写的话，栏杆会横切灯籠的底座。

4. 读数

  • 逐像素差（after3.png → fence5.png，同机位同冻帧；矩形都是截图 px）：
  • 西侧两段 (128,320)–(192,352)：400 px / max 187（其中 80 px 落在石灯籠那一格里， 是栏杆从竿两侧透明缝露出来的部分）

  • 两列花床 (128,192)–(320,320)：0 px——这一笔没碰花床
