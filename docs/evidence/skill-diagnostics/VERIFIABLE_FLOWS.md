## 4. 四类验证边界有没有混称

没有把 5.2 / 5.4 升级成「已验证」这种硬混称，但有两处口径不对齐：

1. **`[实测]` 不等于 5.1。** §5.1 的证据要求是「命令原文 + exit code + 本次读数」；文中 `[实测]` 多数只写「通过」，没有 exit code。按 §5.6，这种只能落到 5.4（人工声称跑过），或补读数后升到 5.1。全文的 `[实测]` 里，只有流程 5 与流程 9 给了可复核的读数。
2. **`[证据]` 不等于 5.3。** 它的定义是「读自已归档的证据文件」，没有确认人、时间、对象三样，按 §5.3 不成立；文中每处都补了「不代表当前值」，所以它**不是**在冒充通过——这是这套三值标签比四类边界更诚实的地方：它把「历史读数」和「本次执行」分开写了。缺的只是与 5.1–5.4 的映射表。

结论：**没有把 SKIP 折算成绿，也没有把 AI 评估当成自动验证**；混的是「实测」与「有 exit code 的自动验证」这两档。补一列退出码即可对齐，不必改判据。

## 5. 结论

- 四块里 **2 强 2 弱**：工具能力与校验机制强（10 条全有反向用例，入口本身有必红自检）；工作流程与反馈闭环弱（无图、无登记处）。
- 三件套 **0 / 3**，缺的是形态不是内容。
- 该文档**不需要重写**：它的正文信息量足够，缺的是 ID 与三张表。§7.4 的「已有有效设计原样保留，只补缺的那块」正适用于它。

## 6. 本轮只做了一件：总表 ↔ 汇总入口的互指断言

选了「互指」这一件，理由：

- 它是这份文档里**唯一一条不改正文就能机器判**的约定。「入汇总」列声称与 `world-client/scripts/verify-all.mjs` 的注册表一致，而这个一致性现在只靠人读命令去猜；
- 不一致是**静默**的：注册表加了流程忘了写进总表，总表从此少一行；某行标「已入」而注册表没有，读者照着表找入口会落空。两种都不会让任何现有闸门出声。

产物：

| 文件 | 作用 |
| --- | --- |
| `world-client/scripts/audit-verify-flows.ts` | 按文件名把总表每行与注册表每项对上；四条判据：已入必须对上、未入必须对不上、注册项必须有行、入汇总必须读得出 |
| `world-client/test/audit-verify-flows.test.ts` | 1 条对照 + 4 条坏样例，每条都只改一处 |
| `world-client/scripts/verify-all.mjs` | 加 `--json`：把注册表原样吐出来给上者读，不解析源码 |

「应该通过」的对照与四条坏样例：

```text
对照：真实总表与真实注册表互指一致，0 处
坏样例：把「已入」写成「未入」，而注册表里确有对应项 → ROW_MARKED_NOT_IN_AGGREGATE
坏样例：把「未入」写成「已入」，注册表里没有任何对应项 → ROW_NOT_REGISTERED
坏样例：「入汇总」写成读不出的值 → ROW_AGGREGATE_UNREADABLE
坏样例：注册表多一条总表里没有的流程 → CHECK_WITHOUT_ROW
```

`node --test test/audit-verify-flows.test.ts`：5 pass / 0 fail。真实文档当前 **0 处**——互指现在是成立的，这条断言的价值是**防漂移**，不是今天挑错。

它拦不住什么（写死，免得被当成全能）：读不懂判据摘要与正文是否一致、读不懂「未执行」是否真的没执行、读不懂两处读数谁对、认不出「同一流程换了脚本但两边没共用一个文件名」。warn 期，未接 CI。
