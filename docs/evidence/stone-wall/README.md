# 花径矮石垣 · 2026-11-09

设定集 p110–111 的「石垣」，原来的状态是一件都没有（`docs/OPEN_ISSUES.md` N 节第 3 条）。
这一笔新增 `kind: 'stone_wall'`，**每帧 0 条命令、24 色不新增、不改通行**。
**依据等级 B：只有仓库转述，没有一手画册证据**（本机画册 PDF 99 页、无文字层，对不上
p110–111）。所以这是「按『石垣』二字推的近形」，**不宣称还原设定集**。

## 1. 做了什么

| 位置 | 改动 |
|---|---|
| `world-client/src/settings/types.ts` | `SettingScenery['kind']` 加 `'stone_wall'` |
| `world-client/src/settings/load.ts` | 装载期闭集 `SCENERY_KINDS` 加 `'stone_wall'` |
| `world-client/src/render/setting-scenery.ts` | `stone_wall` 分支 + 共享纹理名 `STONE_WALL_TEXTURES` / 高度 `STONE_WALL_H` |
| `world-client/src/settings/dengchao/pack.ts` | 8 件，花床北缘 `y20`，`x3..10` |
| `world-client/test/stone-wall.test.ts` | 闭集 / 落地 / **连续** / 未知 kind 仍 throw |

**一件 = 一格**（8 件在 `x3..10, y20`）。与木栅同一套理由：depth 必须按行算
（`world-client/src/render/scenery-depth.ts`），跨多格的长条只有一个 depth，就没法与
站在不同行的人分别判前后。

**两张纹理贴 8 次**。砌缝要左右错开（下节），两版按 `x` 奇偶交替使用；8 件共用 2 张，
不是 8 次 `generateTexture`。

**落在北篱那一行**：O0 记的北篱是 `x2..11 × y19..20`，墙占 `y20`，**不占任何可走格**
（可走内里是 `x4..9 × y21..27`）。

## 2. 形制：16px 三段，齐胸

| 段 | 行 | 画法 |
|---|---|---|
| 笠石（压顶） | 0–2 | `plaza` 压 **0.55**（不是纯 `plaza`），顶行再压 `pale` 0.2 |
| 出檐影 | 3 | `ink` 0.3，一行 |
| 墙身 | 4–13 | `stone` 打底，两皮错缝；缝用 `ink` 0.24（**不是实色深线**） |
| 墙脚 | 14–15 | `ink` 0.3 / 0.14 两行 |

高度 16px，村民 18–20px——这是**齐胸的挡土墙**，不是把人挡住的院墙。再高会把花床后的
视线全吃掉；再矮（12px 试过）读成一条横杆。

砌缝的横竖都照 `scene-artbook.ts` 的 `drawQuay`（堤身：`stone` 底 + `ink` 0.24 缝 +
顶上压一皮亮石）。仓库里那道堤已经读成「砌起来的石体」，没有另发明一套画法。

**两版交替**：单版平铺会在 16px 网格上形成等距竖缝的节奏，读成「贴了壁纸的墙」——
花墙那一轮吃过一次（点阵读成壁纸感）。所以竖缝位置按 `x` 奇偶换一版。

## 3. 只做东西向（沿用木栅的结论，没有重试）

木栅那一轮已经用四张 1:1 对照图钉死：**这套投影里「走向」和「高度」都落在屏幕竖直
方向**，南北向的栅栏栏杆与立柱在屏幕上都是竖线，谁遮谁都分不出，四种画法全部读成
「一根带节的木杆」（见 `docs/evidence/fence/README.md` §2）。石垣的走向同样是屏幕
竖直方向上的线，所以没有再抓四版——**只做东西向的花床北缘一道**，东西两翼的墙没做。

这是几何结论，不是取舍。要补东西两翼，得先解决「竖线读不出体积」这件事本身。

## 4. 五版试错（每一版都抓了 1:1 图）

| # | 画法 | 1:1 下的读法 |
|---|---|---|
| v1 | 12px：3px 压顶 + 6px 墙身 + 2px 影，压顶取纯 `plaza` | 一条浅色横杆，和木栅没有区别 |
| v2 | 18px，照 `drawQuay` 的错缝砌（三皮） | 读成墙了，但太高、太亮，像一面水泥挡墙 |
| v3 | 16px，墙脚压 `soil` **0.28** | 墙身整个糊进草地，只剩顶上一条白横梁 |
| v4 | 去掉压暗，压顶下方加 **2px** 投影 | 帽与身断成两截，像一根白梁架在石墙上 |
| v5 | 压顶改 `plaza` **0.55**、投影收成 1px | 成：一整道石体，压顶只亮一档 |
| v6 | 墙脚影 0.34/0.18 → 0.30/0.14 | 定稿（只是把脚下那道影压淡一档） |

两条可复用的经验：

1. **压顶不能取调色板的亮档原色**。灯潮界的 `plaza` 是 `#7d8984`，`stone` 是
   `#52666a`；`plaza` 直接画上去，1:1 下是近白的一条，整件读成「悬空的白横梁」。
   压 0.55 的 `plaza`，仍在石族里、只亮一档。
2. **墙脚不能压太狠**。0.28 的 `soil` 让墙身和草地同亮度，1:1 下墙身整段消失——
   体积感是靠「墙身比草地亮」撑起来的，不是靠脚下那道影。

## 5. 读数

口径：`?world=dengchao&time=noon&feed=off&ledger=off&debug=1&now=960`、1010×700、
世界冻住、潮位钉 1、晴、灯 / 摊 / 幌 / 烟四支动态全关、180 帧沉降、
相机 `scrollX=0 / scrollY=240`（`centerCameraOn(72,400)`）。

- **逐像素差**（`fence5.png` → `wallF.png`，矩形都是**截图 px**）：
  - 石垣那一带 `(90,150)–(380,205)`：**7,168 px / max 98**
  - 村民 `(725,415)–(785,495)`：**928 px / max 203**——这是噪声，不是改动
    （下面「确定性」那条会把同一块地方也差出 928 px）
  - **其余全部 0 px**
  - 全图 8,096 px，正好 = 7,168 + 928
- **确定性**：同配置双跑，**石垣那一带 0 px、其余 0 px，只有村民那块 928 px**。
  也就是说这一帧除了那名村民，逐像素确定；改动与噪声能干净地分开。
- **命令数不进统计**：石垣是 Image，`renderStats()` 只数 Graphics 的 commandBuffer。
  `graphicsObjects` 两边都是 **119**。
  **`totalCommands` 这一笔读不稳**：同一份代码连续两跑读到 **20,429** 与 **20,085**，
  而两跑的像素差只落在那一块村民身上（928 px）。8 件石垣在场时两个值都出现过
  （`wall1/wall2/wall4` 读 20,085，`wall6/wall7` 读 20,429）。
  所以：**这个 344 的摆动与村民状态同源，既不能算石垣的增量，也不能算任何一笔的增量。**
  附带一条：`docs/evidence/fence/README.md` §4 写的「O4 单时刻噪声 ±120」**估小了**——
  实测摆动至少到 344。要拿这条读数做判据，得先把村民按住。
- **预算闸**：`check-ground-shadow` 绿，实测峰值 **28,076**、天花板 `34,666`、债务 0。
  与木栅那一笔读同值（28,076），与庭心石作那笔的 28,076 也同值——**没有变化**，
  石垣是 Image 不进命令统计。
