# 庭心石作的形制（+0 条命令）· 2026-11-09

花径中央那件 `statue` 本轮只改**形制**：不动件数、不动位置、不动预算、不新增颜色。
**依据等级 B：只有仓库转述，没有一手画册证据**（本机画册 PDF 99 页、无文字层，对不上
p110–111）。所以这是「按转述推的近形」，**不宣称还原设定集**。

## 1. 改了什么

| 项 | 改前（四条 `fillRect`） | 改后（石灯籠） |
|---|---|---|
| 纹理 | 16×19 ＝ 1,216 byte | **16×24 ＝ 1,536 byte** |
| 基座 | 一块 16×8 的大方砖，没有分层 | **两级基座**：14 宽 × 4 高 / 10 宽 × 3 高，中间压一道缝 |
| 身 | 一根 8 宽的柱 | **竿**：6 宽 × 5 高，左棱受光、右棱落影 |
| 台 | 无 | **中台**：8 宽 × 2 高，下沿三个凹口当莲弁纹样 |
| 灯位 | 无 | **火袋**：8 宽 × 5 高，正面 **4×3 的暗窗**（不是灯窗） |
| 顶 | 无 | **笠**：12 宽出檐 + 8 宽顶面；**宝珠** 4 宽 × 2 高 |
| 那道蓝带 | 横贯 12 px 的实色 `water`，读成一条浮在石头上的蓝条 | 删掉，改成基座与檐底的结构线 |

源码：`world-client/src/render/setting-scenery.ts` 的 `statue` 分支（`bakeLayer` 回调）。
广场那件 `(26,28)` 与庭心 `(4,25)` **共用同一支形制**，两处同步换掉。

## 2. 为什么这么画

- **靠轮廓的进出做结构，不靠描边**。六段各自比下面一段窄或宽：14 → 10 → 6 → 8 → 8 → 12，
  剪影本身就能读出「叠石」。花墙那一轮已经证过：在 24 色下画一条实色 `deepShade` 分割线，
  会被读成两块拼板之间的缝（见 `docs/evidence/flower-wall/README.md` §2）。
- **接缝一律用 `ink` 低透明压在石面上**（0.28–0.35），与 `scene-artbook.ts` 的
  `drawQuay` 同一套画法。这样缝仍是「石头上的阴影」，不是「石头之间的空隙」。
  纹理内部是 2D canvas 合成，`alpha<1` 叠在不透明石面上得到的是**不透明**结果，
  不会透出草地。
- **窗要暗**。这一处没有光源：给石作补灯实测 **+306 条**、超天花板（见
  `docs/OPEN_ISSUES.md` O2）。所以火袋画的是暗窗——形制上有灯位、功能上没有灯，
  夜里它就该是黑的。
- **不动位置**。石作仍在 `(4,25)`，与上一行花圃在 `y392..396` 有 **4px 几何重叠**。
  这是行序本来就允许的（花圃行 24、石作行 25，石作 depth 高 16），不是遮挡错误。
  广场那件 `(26,28)` 的下半截本来就被街灯串挂的纸灯挡住（改前改后是同一条串、同一位置），
  也不是这一笔造成的新遮挡。
