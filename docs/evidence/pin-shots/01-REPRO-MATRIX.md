# 剩余 12 张的「钉住可复现性」实测（只测不改）

> 口径：`PIN_SHOTS=1`（抓拍脚本里的环境开关，默认关闭，正常抓拍一字未改）。
> 每张拍前：`freezeWorldClock()` + `pinShotState(当天 12:30, 潮位 0)` + 镜头钉整格；
> 拍完立刻 `unpinShotState()` + `unfreezeWorldClock()`，世界照原样往下跑。
> 三次跑分别是 run1 / run2 / run3，同一构建、同一机器、同一脚本、同一端口（5210）。
> 未重录任何基线，未改阈值，未动存档 v5。

## 结论

1. **世界侧的差已经全部被钉子吃掉**：钉住"呈现时刻 + 潮位"之后，**没有任何一张再出现草地色阶整片差**（乙 类 0 张）。
2. 剩下的差只有两类，都不在世界状态里：
   - **内建动画**（烟柱、雨丝）——逐帧相位不同，钉世界钟不钉帧时钟；
   - **页面/截图链路**——底栏"第 N 分 SS 秒"读的是未钉住的快照时间；调试面板让画布落在半像素位置，合成器重采样出 1 级全屏差；`08` 的元素截图连尺寸都不稳定。
3. 唯一三对全 0 的是 `01-salute`（上一轮已修）。其余 12 张本轮**一张也没到 0**。

## 方法

- 新增开关 `PIN_SHOTS`（`world-client/scripts/smoke.mjs`），默认关闭。打开时逐张：
  - `02`：`pinShotCamera()` 之后钉住，镜头沿用（小人在铺子里，机位是整格）；
  - `03`：在"刚交付"那一拍的就地 `freezeWorldClock()`（`waitForFunction` 回调里），再钉机位；
  - `04`：`pinShotCamera()` 之后钉住（她还在跑向屋檐的半路）；
  - `05`：在"新楼已出现且仍在施工"那一拍就地冻钟，机位钉在新楼中心；
  - `06`：`pinShotCamera()` 之后钉住；
  - `07/08`：保持原口径（本来就已经冻钟 + 钉死 (768,576)），**不再额外加钉**，这样测的是"它们当前口径"。
- 每张拍完解钉解冻；`check` 读的仍是真快照，未动任何断言。
- 比对工具 `docs/evidence/salute-nondeterminism/diff_runs.py` 扩了第三判据：
  **结构差** = 可见差（任一通道 ≥8）掩膜的 8 连通块：块数、最大块面积、最大块 bbox 与外接尺寸。
  `tag` 只按宽高猜形状（`text` / `sprite` / `ground` / `mixed`），**不是判据**，只作认块提示。

## 每类的口径建议与代价（不是实现）

### 乙（本轮 0 张，但机制上要写清）

- **要补钉什么**：`presentedNow`（已钉）+ `tide.level`（已钉）。两者缺一：
  - 只钉时刻不钉潮位 → `tideView`/`settingScenery` 仍按真实 `tide.level` 压暗草地，跨 0.3 阈值时整片翻色（上一轮 `01` 的 24.765%、`06` 的 10.4% 就是这个）；
  - 只钉潮位不钉时刻 → 小人帧、雾、ambience 相位仍随逻辑步漂。
- **代价**：画面固定在"当天 12:30 + 退潮"，不再是抓拍那一刻的真实潮位/时段。快照仍报真实值，所以 `phases`/`palette`/`render-budget` 读快照的判据不受影响；受影响的只有"截图这一张的画面语义"。

### 丙（本轮 0 张）

- **是否只能钉精灵位置/相机整数对齐**：是。相机 `pinShotCamera()` 已经把 `Math.round(pos)` 落成整格；只要不追着实时位置走，就不会跨格。
- **代价**：镜头不再跟着人走——**构图会偏最多一格 16px**；若小人正好在格边界，必须选一个固定锚点格，画面和"跟拍"差半格到一格。

### 丁（4 张：烟柱、雨丝）

- **是否只能降级成结构判据**：是。这些动画的相位由**帧时钟**（`delta` + `tick`）驱动，不是世界时间：
  - 烟柱：`this.tick % 3 === 0` 才发射，粒子寿命按 `delta` 推进；
  - 雨丝：`createWeatherView` 的 `Math.random` 没有种子（smoke 未设 `__RAIN_SEED__`），且按 `delta` 移动。
  冻世界钟只能冻"世界"，冻不住"帧"。所以逐像素判据在这块只能二选一：冻 `delta`（把 `renderSnapshot` 的 delta 传 0，属于改渲染分支，代价是动画停在半空），或者**降级为结构判据**。
- **降级的损失**：判"烟柱在不在、雨在不在这块 bbox 里、连通块面积是否在区间内"，不再保证逐像素。代价是**动画的美术回归（颜色/形状/密度）会漏**；只能靠人工看片或另一种"取 N 帧里的极值"来兜。建议判据写成"动画块内不算逐像素，只算存在性与面积区间"。

### 戊（8 张：页面/截图链路）

- **底栏时钟**（`04/05/06`）：底栏读的是 `snapshot.now`，不是 `presentedNow`。要么把世界时间也钉死（`jumpWorldClock(当天分钟)` 后再截），要么截图时隐藏/固定底栏。代价：前者会改"抓拍那一刻的世界时间"，后者会少一截 UI 证据。
- **调试面板 → 画布半像素**（`07`×4）：面板宽度随事件文字变化，`#stage` 跟着落在半像素，合成器重采样出全屏 1 级差。要么把 `#stage` 绝对定位到整数像素、要么截图只截 `#stage` 元素而不是整页。代价：改页面布局属于动 `index.html`/CSS，本轮边界内没做；只截元素则会丢掉面板本身的证据（而 07 恰恰是面板镜头）。
- **元素截图尺寸不稳**（`08` 200/400）：`locator('#stage').screenshot()` 在超过视口的尺寸上靠拼接，滚动条有无都能改 4–88px。要么先 `overflow-y: scroll` 常驻 + 固定视口，要么改成按 DPR 缩放后的 `page.screenshot({clip})`。
- **明确一句**：戊这一类**只能靠夹具兜住，不能靠判据**。判据（0.2% 闸门）在戊 上永远会红，且红得没有信息量。

## 01 构图结论

**存在确定的"状态"，但不存在只由时刻决定的时刻。**

搜索方法（两轮）：

1. 同一会话里从 06:00 起按 5 分钟步长 `jumpWorldClock` 扫到 22:00，每次等两人站定（`walking=false` 且连续 3 次指纹相同），记 `day / minuteOfDay / 两人 pos / tide`（`day-scan.json`）。
2. 直接跳单点做对照：从 06:00 **一次跳到 07:05**，看落点是否与扫描一致（`probe-candidate` 三次）。

结果：

- 扫描里确实有大量「两人都站定 + 莞尔在祭坛 (48,36)」的窗口：
  - **day 0 · 07:05–07:35**：莞尔 (48,36)、阿雾 (40,40)（农田边）；tide 0 / 0.887 / 0.246 / 0.594 / 0.509 / 0.306 / 0.916
  - **day 0 · 08:45–09:15 / 10:25–10:55**：同上位置
  - **day 0 · 12:05–13:55**：两人**都在** (48,36)（安静段都回锚点，重叠）
  - **day 0 · 14:05–15:20 / 16:35–17:00 / 18:15–18:40 / 19:55–20:20 / 21:35–21:55**：莞尔 (48,36)、阿雾 (56,33)（街口）
- **但对照实验否定了"时刻即答案"**：从 06:00 一次跳到 07:05，三次跑落点都是 **莞尔 (40,40)（农田边）、阿雾 (56,33)（街口）**，不是扫描里的 (48,36)/(40,40)。原因是作息走的是 `routineIndex`（已经走过几拍），不是 `now`。同样的 07:05，历史不同，落点不同。
- 唯一能**只靠时刻**收拢的是安静段（12:00–14:00 内 `routineFor` 强制回锚点），但也必须**等当前这一拍待够**：首次探针从 12:00 起跳，两人到 **12:50** 才都落到 (48,36)；12:00–12:45 期间仍是 (40,40)/(56,33)。

**给 01 的可用候选（状态谓词，不是钟点）**：

```
jumpWorldClock(750)                     // 12:30，安静段
waitFor(两人 walking=false 且 莞尔 pos == altar (48,36))
→ 此刻两人都在 (48,36)，重叠；派单 → 莞尔在祭坛行礼
```

`07/08` 已经在用这条路径（12:30 + 等指纹稳定 + 钉死 (768,576)），三跑世界内容一致，可作为旁证。
代价：两人重叠在祭坛，**回不到基线那种"莞尔在祭坛、阿雾在街口/农田"的构图**；若要那种构图，只能靠"等状态"（莞尔在祭坛 + 阿雾在 (40,40) 或 (56,33)），最长要等一个作息周期（约 100 世界分钟 ≈ 200 秒实时 @speed=30），且无法只靠钟点复现。

## 单测清单（`pinShotState` 的最小覆盖）

现在 `pinShotState` 零单测。建议按分支列 8 条，全部是"输入 → 渲染输入"的纯断言，不需要新框架：

1. **钉住 now 生效**：给定 `snapshot.now = N`，`pinShotState(N + 100, …)` 后，小人帧索引 / 雾 / `ambienceView` 的入参等于 `N + 100` 推出的值，而不是 `N`。
2. **钉住 tide 生效**：`pinShotState(_, 0)` 后 `tideView`/`settingScenery` 收到 0；草地色等于基线 `(45,59,46)`。
3. **解钉还原**：`unpinShotState()` 后同一 snapshot 的渲染入参回到 `snapshot.now` / `snapshot.tide.level`。
4. **不改快照**：pin 前后 `Oracle.view()` 深比较完全相等（尤其 `now`、`tide.level`）。
5. **不动冻钟语义**：`worldClockPinned()` 在 pin/unpin 前后不变；pin 不会让 `snapshot.now` 前进或停住。
6. **非法输入不生效**：`pinShotState(NaN, 0)`、`pinShotState(0, Infinity)` 不改变任何渲染入参（现有 guard）。
7. **幂等**：同参数连续 pin 两次，渲染入参一致；跨不同参数再 pin 一次以最后一次为准。
8. **phaseView 拷贝分支**：钉 now 到与 `snapshot.phase` 不同的时段（如 noon→dusk）时，`phaseView` 收到的是 `{...snapshot, now}` 拷贝，`Oracle.view().now` 不变（防止把钉子写回快照）。

## 三道闸门会不会被钉子影响

**不会。** 理由：

- `pinShotState` / `unpinShotState` 只由 `smoke.mjs` 调用（全局 grep 只有 `smoke.mjs` 与 `SandboxScene.ts`）；`check-phases.mjs` / `check-persistence.mjs` / `check-render-budget.mjs` 都不碰它。
- 默认 `pinnedPresentedNow === null` / `pinnedTideLevel === null`，`renderSnapshot` 里走的是 `?? snapshot.now` / `?? snapshot.tide.level` 原值，**渲染路径与改前逐字节等价**。
- 三道的判据读的是 `Oracle.view()` 快照与预算计数，`pinShotState` 明确不写快照（第 4 条单测钉的就是这个）。
- 本轮**没有跑**这三道（用户要求"只测不改"，且不占 5191/5202/5203）；要进闸门前应把上面 8 条单测补上并跑一次三道基线对照。

## 能不能开始重录

**不能。**

- `01` 的机制已经成立（三对 0），但**构图必须换**（上一轮已因"等两人站定"漂到齿轮塔；本轮给出的是"12:30 安静段 + 等祭坛"路径，画面是两人重叠在祭坛）。
- 其余 12 张：0 张到 0。`02/03/04/05` 是烟柱/雨丝（丁），`06` 是底栏时钟（戊），`07/08` 是画布半像素与元素截图（戊）。
- 重录前置（按顺序）：
  1. 先定 01 的新构图（状态谓词 + 是否接受两人重叠）；
  2. 丁 类四张改成结构判据或冻 delta（二选一，并写清损失）；
  3. 戊 类：底栏时间钉死或隐藏；`#stage` 整数定位 / 只截元素；`08` 固定视口 + `overflow-y: scroll`；
  4. 以上都绿后，才允许一次性重录。
