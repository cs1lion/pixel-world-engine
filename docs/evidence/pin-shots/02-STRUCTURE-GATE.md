## 二、01 为什么不再走 `jumpWorldClock(750)`

`jumpWorldClock(750)` 会把两人拉回 12:30 的锚点，(48,36) 重叠，丢掉「祭坛 + 街口」的构图。
本轮改用「钉时刻 + 等状态」：先 `pinShotState(07:05, 潮位 0)`，再循环推进世界，直到
莞尔 (48,36)、阿雾 (40,40) 且两人 `idle` / 不走 / 无活动任务；硬超时 300 秒实时，
超时直接判红并打印 `day/minuteOfDay/pos/mode/walking/taskId`，不降级、不改构图。

三跑 01 截图逐字节相同（精确 0、可见 0、最大差异块 0），说明这条路径本身是确定的。

## 三、戊 8 张的三处夹具

1. **底栏时钟**：07/08 段原本只 `freezeWorldClock()`，画面仍按快照的 `now` 上色，而跳 750
   之后世界还会多跑半分钟到十几分钟，两跑冻结点不同。先在「站定」后把 `now` 回拨到整点
   12:30 再冻，再 `pinShotState(12:30, 0)` 钉住呈现时刻——底栏「750 分 00 秒」与状态行
   （「莞尔：去祭坛」这类）都不再随真实冻结点换词。
2. **站定判据**：原来的「位置指纹两次相同」会抓到两人在瓷砖之间停一拍的空档，冻下来
   落点能差半个画面（实测莞尔有时在祭坛前、有时在左下角）。改为 `idle` + `walking === false`
   + `taskId === null` 且位置连拍三下不变（450ms）。
3. **`#stage` 整数盒**：`#stage` 是 `width: fit-content`，换视口后被撑宽 2～6px
   （963 → 967/969，4x 截图于是 3868/3876 漂移）。首次量到的整数盒直接钉死
   （`width/height/flex: none`），并禁小数缩放；8 系列改用固定整型视口 + 常驻滚动条
   （`scrollbar-gutter: stable`、`overflow-y: scroll`），每次换视口先 `scrollTo(0,0)`
   再量——`page.screenshot({clip})` 的裁剪盒是**文档坐标**，页面停在上一视图的滚动位
   会把 08-100 裁成 963×219。

结果：06、07×4、08×3 三跑精确 0，尺寸一致（08 的 4x 不再是 3868/3876 两值）。

## 四、结构判据（丁 4 张）

`screens-diff.py` 新增结构档：

- `structure_report(mask)`：对可见差掩膜做 8 连通块，输出 `coveredPx` / `largestAreaPx` /
  `largestBbox` / `blocks[:10]`；每条记录始终写 `structure`。
- `structure_assertion(struct, rule)`：`area > 0 且 minArea ≤ area ≤ maxArea`，理由码
  `pass` / `no-diff-region` / `area-out-of-range`。
- `--structure-spec <json>`：命中 spec 的记录写 `structureAssertion`，payload 增加
  `structureSpec` / `structureFailures`，有失败则 `SystemExit(1)`。

阈值（`structure-spec.json`）：02/03 烟柱 3,000–5,200 px；04 雨幕 38–85 px；05 烟柱 60–160 px。
3000–5200 与 38–85 来自上一轮的三跑实测；05 的 60–160 是上一轮读数（80–112）的包络。

实测（三对）：

| 文件 | 最大块（1-2 / 2-3 / 1-3） | 断言 |
|---|---|---|
| 02 | 1840 / 1964 / 1068 | 全部 `area-out-of-range` |
| 03 | 5032 / 4956 / 4604 | 全部 `pass` |
| 04 | 27292 / 80 / 27292 | 1-2、1-3 `area-out-of-range`；2-3 `pass` |
| 05 | 112 / 112 / 80 | 全部 `pass` |

**代价（必须写进判据说明）**：结构档只看「两跑的差异块有多大、在哪」，**烟柱/雨幕的颜色、
形状、密度回归会漏**。纯色板偏移、柱形从细高变粗矮、雨从疏变密但面积不变，这套判据都不会红。

**04「整幅平移」旧定性作废**：±4px 搜索在本轮所有记录上都是 `dx=0, dy=0`，此前那条
「整幅平移」判断不成立，作废。

## 五、04 的读数为什么忽绿忽红

04 的雨由 `Math.random` + delta 推进，两跑的雨幕相位完全独立：硬碰巧对齐时差异块只剩
80px（2-3 通过），错开时整片雨幕都不同（27,292px，1-2、1-3 失败）。同一组夹具、同一份
代码，读数跨两个数量级——这说明**差分型的「雨幕存在」度量的是相位差，不是存在性**。
02 同理：烟柱是粒子按 delta 推进，两跑相位接近时差异块只有 1,068–1,964px，够不到 3,000。

这不是阈值松紧的问题：把区间放宽到能同时包住 80 和 27,292，判据就等于没有。
结论是这条判据对 02/04 不成立，需要改成**单幅画面里的存在性度量**（例如按调色板里
烟柱/雨丝的专属色计数，或与「同场景无粒子」对照帧比），而不是两跑差分。

反向用例（`reverse-structure-check.py`，证据在 `reverse/`）：

| 用例 | 最大块 | 期望 | 实测 |
|---|---|---|---|
| 真实 02 两跑 | 1840 | PASS | FAIL |
| 真实 04 两跑 | 27292 | PASS | FAIL |
| 合成「烟柱压到 2900px」 | 2900 | FAIL | FAIL |
| 合成「雨丝全无」 | 0 | FAIL | FAIL |

反向用例证明结构档**会红**（2900 / 0 都判红），不是永远绿；同时它也证明当前阈值对
真实的两跑读数会红——两头都如实记录。
