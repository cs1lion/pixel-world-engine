## 一、结论（一句话）

**是代码/世界状态不确定，不是浏览器/WebGL/GPU。**

抓拍发生在「等 `#reply` 回执」之后，世界在 `speed=30` 下继续跑：两跑停在不同世界时刻 →
潮位跨过草地的淹没阈值（`world/tide.ts` 里 `TERRAIN_HEIGHT.grass = 0.3`）→ 整片暗地/植被
多一层 `ink + water` 半透明覆盖，蓝通道恒 +9；同时两个居民还在赶路，精灵按 `pos` 位移 1–2px。
同状态下的 GPU 输出是逐字节确定的（下面第 4、5 节）。

## 二、证据链

### 1. 差异长在哪：不是滤镜，是整格地形

修前 B1/B2 的 `01-salute.png`：

| 指标 | 值 |
|---|---|
| 精确差（任一像素任一通道 ≠0） | 25.096% |
| 可见差（任一通道 ≥8 级） | **24.765%**（235,124 px / 960×640） |
| 全图最大通道差 | 220（来自状态栏文字重排，不是地形） |
| 可见差 bbox | x26–985 / y69–708 |

按颜色对拆开（同一像素对计数）：

| 旧色 | 新色 | 像素数 | 占比 |
|---|---|---|---|
| `(45,59,46)` | `(46,63,55)` | 216,344 | 92.0% |
| `(27,33,28)` | `(31,42,40)` | 8,288 | 3.5% |
| `(74,79,66)` | `(119,125,118)` | 4,800 | 2.0% |

- 第一对 `(45,59,46)→(46,63,55)` 的 Δ = **+1/+4/+9**，正好是「暗色草地/植被」；
  `(27,33,28)` 是草地上的土点纹，`(74,79,66)` 是田块里的石粒。
- 差异呈**四块连续矩形**：x26–441/y69–260、x26–441/y517–708、x698–985/y69–260、x698–985/y517–708
  —— 正好是祭坛镜头左、右、上、下四块**草地田块**。
- 石板广场、路、深色 `ink`、石墙的像素计数**完全不变**。
- 排除四块草地矩形后再看：只剩 5,660 px，全部落在两个小人的轮廓上（`nongrass_overlay.png`），
  颜色对是 `ink↔plaza`、`ink↔stone`、`cloakDark(34,58,77)↔cloak(48,80,107)` —— 精灵整体位移 1–2px。

→ 不是整屏滤镜、不是调色板、不是 PNG 编码；是**整格地形上的一层半透明覆盖** + **精灵位置**。

### 2. 潮位阈值：为什么正好是 +1/+4/+9

`world/tide.ts`：

- `TERRAIN_HEIGHT`：`grass = 0.3`、`tree = 0.42`、`stone/plaza = 1.2/1.3`。
- `isFlooded(terrain, level)` 对**整格**返回布尔：潮位一过 0.3，整片草地**同时**被淹（不是渐变）。
- `render/tide-view.ts` 对被淹格：先 `ink` 压暗 `0.12 × min(1, level × 1.4)`，再叠 `WORLD.water` α `min(0.46, level × 0.46)`。

level 刚过 0.3 时：压暗 `0.05`、水 α `0.138`；对底色 `(45,59,46)`、`water=(61,107,122)`：

```
r = 45*(1-0.138) + 61*0.138 ≈ 46.1
g = 59*(1-0.138) + 107*0.138 ≈ 64.0
b = 46*(1-0.138) + 122*0.138 ≈ 55.1
```

≈ `(46,64,55)` —— 与观测到的 `(46,63,55)` 一致（差 1 级来自压暗项）。**算术与像素对上。**

### 3. 同进程潮位扫描：草地颜色随 `tide.level` 单调变化

`probe-salute.mjs MODE=times`：同一页面会话里逐个 `unfreeze → jumpWorldClock(minute) → freezeWorldClock`
再连拍（世界时钟冻结，只有 `now` 不同）。`gl.readPixels` 读回与 PNG 截图**完全一致**：

| 世界时刻 | `tide.level` | 草地读回主色 |
|---|---|---|
| 10:00 | 0.778 | `(36,48,42)` |
| 10:15 | 0.027 | `(45,59,46)` ← 干 |
| 10:30 | 0.977 | `(34,45,42)` |
| 10:45 | 0.823 | `(35,47,42)` |
| 11:00 | 0.007 | `(45,59,46)` ← 干 |
| 11:15 | 0.757 | `(35,48,42)` |
| 11:30 | 0.960 | `(34,46,43)` |

潮汐周期 10–14 世界分钟；`speed=30` 下 **约 20–28 秒实时一个周期**，阈值翻转只需要
≈0.002 级差 ≈ 0.8 世界秒 ≈ 27ms 实时。两跑的抓拍时刻只要差 1–2 秒实时，就会落在阈值两侧。

同时注意 `villager.pos.x` 在 46.95 → 46.00 之间连续变化（她确实在走动），对应第 1 节的精灵位移。

### 4. 排除截图链路（DPR / 合成 / PNG 编码）

同一帧里 `gl.readPixels`（GL 原点左下，取暗地块）与 `page.screenshot` 的对应像素**逐字节相同**
（上面第 3 节的 `readback` 主色 = 截图主色，两个都取 `480×320` 的 drawingBuffer）。
→ 截图链路不是成因；锅不可能落在编码/DPR 缩放上。

### 5. 同进程连拍 = 0：每帧渲染没有抖动/量化/浮点不确定

两个独立进程各跑一次 `MODE=frozen`（冻钟后隔 3 秒连拍两张同一帧）：

| 进程 | `now` | `tide.level` | A1 vs A2 精确差 | 可见差 | maxdelta |
|---|---|---|---|---|---|
| frozen1 | 37,821,000 | 0.985 | **0.0000%** | **0.0000%** | 0 |
| frozen2 | 37,818,000 | 0.981 | **0.0000%** | **0.0000%** | 0 |

→ 只要世界状态不变，同一后端**逐字节复现**。没有抖动、没有 MSAA resolve 时机差、没有 sRGB 往返误差。

### 6. 跨进程冻钟：只剩「冻在哪一个逻辑步」

`frozen1` vs `frozen2`（两个进程各自冻钟，落点差 1 个逻辑步 = 3000ms 世界时间）：

| 指标 | 值 |
|---|---|
| 精确差 | 24.2368% |
| 可见差 | **0.1045%**（992 px） |
| 可见差 bbox | x94–737 / y153–524 |
| 主色对 | `(20,17,13)→(34,45,42)`、`(216,218,211)→(34,45,42)` |

- 两人 `villager.pos` 冻住后**完全相同**（46.90, 36.00）→ 模拟本身是确定性的。
- 但 `tide.level` 0.985 vs 0.981 让草地的**亚级**颜色不同（精确差 24%，可见差接近 0）。
- 992 px 的可见差全在人物/气泡附近：1 个逻辑步里的眨眼（`floor(now/100)%43===0`）、
  呼吸/围巾这类 `now` 派生量，加上气泡位置。

→ 「跨进程」本身不产生不确定；**冻在哪个 `now`** 才产生。

### 7. 代码侧审查清单

| 查了什么 | 结论 |
|---|---|
| `main.ts` / Phaser config 的 WebGL 上下文参数（`antialias`、`premultipliedAlpha`、`preserveDrawingBuffer`、`powerPreference`、`failIfMajorPerformanceCaveat`、`resolution`） | **全部未显式设置**，走 Phaser 3.90 默认；`src/` 全域 grep 无匹配。第 5 节的同进程 0 已排除管线差异 |
| 渲染路径里的 `Math.random` / `Date.now` / `performance.now` | 渲染层**无**；`render/weather.ts` 的雨滴 `Math.random` 有确定性种子开关，且 01 是晴天不画雨 |
| `bake`/贴图生成顺序（对象键序、`Set`/`Map` 迭代序、不稳定排序） | `render/` 下无 `Object.keys` 遍历、无 `.sort(`；bake 用整数 `hash2`；同状态两帧逐字节 0 |
| 24 色量化最近色并列 | 本仓库**没有**「取最近调色板色」的浮点比较；所有颜色是固定调色板常量直取 |
| 抖动/暗角/雾图案是否用世界时间以外的量 | `render/` 无 `frameCount`/墙钟；`fog-view`/`phase-view`/`ambience` 全用 `snapshot.now` |
| 相机是否落在半像素 | `pinShotCamera()` 用 `Math.round(pos.x) * TILE_PX`，实测 `scrollX/Y = 528/416` 整数；两跑一致 |
| `isFlooded` 的阈值语义 | **离散阈值**（0.3），跨过就整片翻转 —— 这就是 24.7% 的来源 |
| `bakeLayer` 的输入是否含时间 | 不含 `now`；同状态两帧 → 0 |

→ 审查没有发现任何「渲染本身不确定」的点，全部指向**状态/时刻**。

## 三、修法（最小改动，夹具，不动判据）

### 改动 1：`src/scenes/SandboxScene.ts` —— 呈现态夹具

`renderSnapshot` 里所有跟时间走的画面只认一对可钉死的值：

```ts
const presentedNow = this.pinnedPresentedNow ?? snapshot.now;
const tideLevel = this.pinnedTideLevel ?? snapshot.tide.level;
```

替换的调用点：`updateVillager(..., presentedNow, ...)`、`weatherFogView.update(..., presentedNow)`、
`tideView.update(tideLevel)`、`settingScenery.update(tideLevel, presentedNow)`、
`phaseView.update(pin 时的一切换成 {...snapshot, now: presentedNow})`、
`ambienceView.update(presentedNow, ...)`、`fogView.update(..., presentedNow)`。

Oracle 只加两个调试钩子（与既有 `freezeWorldClock` 同级别）：

```ts
pinShotState(nowMs, tideLevel)   // 钉住画面时刻 + 潮位
unpinShotState()                // 解开，立刻回到快照值
```

**钉的是画面，不是世界**：`snapshot`、判据、存档 v5、世界语义一概不变。

### 改动 2：`scripts/smoke.mjs` 的 01 段

在**采样回调里**「等两个人站定 → 就地冻钟 → 钉呈现态」，再提交神谕：

```js
await page.waitForFunction(() => {
  const snapshot = window.Oracle.view();
  if (snapshot.villagers.some((villager) => villager.walking)) return false;
  window.Oracle.freezeWorldClock();
  window.Oracle.pinShotState(dayStart + 45_000_000, 0);   // 12:30、退潮
  return true;
}, null, { timeout: 120000 });
```

拍完立刻：

```js
window.Oracle.unpinShotState();
window.Oracle.unfreezeWorldClock();
```

- **为什么要先等站定**：只冻在「行礼那一拍」时，另一个角色（阿雾）可能正走在去街口的路上，
  她的像素位置随世界时刻连续漂，冻在哪一拍就差几像素（中间版本第三跑实测 0.95%，见第四节）。
  两个人都停在锚点上，位置才是可复现的。
- 呈现时刻取**当天 12:30**（与 07/08 的 `jumpWorldClock(750)` 同一口径），潮位取 **0（退潮）**
  —— 与基线里 `(45,59,46)` 的干草地同色，画面不因为「随机落在涨潮」而变。
- 冻在提交之前，命令照样在 `update(0)` 里结算，行礼与气泡停在那一拍（`bubbleUntil` 不随冻钟走）。
- 判据、基线、闸门阈值**一个没动**。
- **构图变了**：等站定的那几十秒里，莞尔的作息把她带到了齿轮塔（原来抓拍时她还在祭坛边赶路）。
  01 依旧是「她停下手里的事行礼」，但**背景从祭坛换成齿轮塔**；这属于必须重录的部分（见第七节）。

## 六、被否的写法

1. **只 `freezeWorldClock()`**：不够。冻结时刻照样可能落在阈值两侧（阈值翻转只要 ≈0.8 世界秒）；
   实测跨进程冻钟仍有 0.1045% 可见差（眨眼 + 亚级潮位）。
2. **只冻在「看到行礼那一拍」+ 钉呈现态**（本轮第一版，run1–run3）：前两跑 0.0000%，
   第三跑 0.9495%（9015 px）：另一个角色阿雾正在去街口，位置比前两跑多走了约 4px。
   → 必须再等「两个人都站定」。
3. **用 `TideOverride` 压住潮位**：`TIDE_OVERRIDE_MAX_MS = 2 分钟`世界时间（`speed=30` 下只有 4 秒实时），
   压不住整场；而且会改 HUD 文案、产生「神谕改潮」的事件语义。
4. **只改相机**：镜头本来就已经钉在整数格（`scrollX/Y = 528/416`）；差异不在镜头。
5. **把 `speed` 调慢**：只是把概率摊薄，不是确定性；世界时刻仍然随实时漂移。
6. **放宽可见差判据 / 改 `screens-diff` Δ 阈值**：明令禁止，且会掩盖其它镜头的真回归。
7. **把 01 的截图挪到「等回执之后 + 冻钟」**：冻是冻住了，但冻在哪一拍仍然随机；
   而且那正是潮位翻脸的地方。
