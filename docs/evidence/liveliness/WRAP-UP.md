# 天气与潮汐这一线 · 收尾清单

分支 `feat/liveliness`。第 1、2 条（潮汐时辰/水位、天气三态与探索雾）与第 3 条
（事件进记忆 + 影响次日行为）都已落地；面板时刻显示也在最后补上。
证据见同目录 [`INDEX.md`](INDEX.md)。

## 做了什么

1. **潮汐**：灯街渡口的潮汐按世界时辰起落，水位读数是运行时量，不写档。
2. **天气三态**：晴/雨/雾按种子排天，只有设定集（`pack.authored`）打开；
   雨里 1.5 倍步速但走得更少，雾里探索范围收紧，18 团雾在图内漂移。
3. **天气事件只进近场记忆**：单次天气变化按 6 格（半条灯街）分组入账，
   目击者用 `sourceMode: 'witnessed'`；镇级本身只落一条 `actorId: null` 的 change。
4. **习惯只认目击**：`heard`（传闻）会进个人时间线，但不进习惯账本，
   否则 6 格规矩会退化成全镇广播。
5. **次日行为改变**：第 0 天淋雨的目击者，第 1 天 13:00 后去摊位提前盖布；
   有/无记忆对照 7 人 / 0 人。
6. **衰减闭环**：记忆强度在**日终**衰减同一条条目（不按天重乘），
   1.0000 → 0.8500 → 0.7225；第 3 天跌破 0.75 门槛，盖布从 6 人变 0 人。
7. **面板因果**：展开条目能看到「因为昨天淋了雨，今天提前收摊」，
   以及 `memoryId` / `eventId`；因果认那句话，不认时间线的 `entry.kind`
   （那是记忆种类 `episodic`/`summary`，不是世界事件种类）。
8. **面板时间线**：每格同时写天序与时刻（`第 1 天 13:00`）；时刻取自事实
   `tick`，查看不到事实写「时刻不明」，真午夜仍显示 `00:00`。三条断言钉住
   13:20 / 00:00 / 无事实三种情况。

## 还差什么

- **天气只改了盖布这一种行为**。撑伞、退到檐下、雾里搁下远行是天气三态的
  **即时反应**，还没接进「昨天怎样 → 今天怎样」的记忆链路；天气对赶集、
  摆摊时长、渡口班次的影响都未验。
- **潮汐与天气的组合未验**。潮汐按时辰、天气按槽位，两条时钟各走各的；
  涨潮 + 雨天、雾 + 退潮这些叠加情形既没有读数也没有行为后果。
- **传闻记忆没有进关系账本**。`heard` 只落在个人时间线；谁把话传给谁、
  传闻会不会改变关系读数，这一线没做。
- **`avoidedBeats` 不落盘**。避让拍数、灯塔雾/探索雾、`preCoveredDay` 都是
  运行时读数；刷新或读档后从零开始，复核必须一次跑完。
- **时间线没有去重**。同一事实的 `witnessed` 与后来的 `heard` 各占一格，
  面板会出现两条内容相同、时刻相同的条目。
- **「今日」列表混着听说条目**。列表按落账日（`createdDay`）分组，但显示的是
  事件发生日；听说昨天的事会出现在今天的列表里，标着 `第 0 天`。分组语义
  要不要改成「事件日」还没定。
- **`content.when` 语义仍混用**。它存的是第几天，`distort` 的时间偏移却按
  毫秒加半天；这次用事实的 `day`/`tick` 绕开了，没有改记忆层语义与存档。
- **`test:buttons` 未验证**。它需要 `dev-live` 的带后端实例；本轮没有起后端，
  不写成绿。
